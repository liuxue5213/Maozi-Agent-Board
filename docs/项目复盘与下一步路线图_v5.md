## 3. 本轮发现的实际风险

1. **真机证据仍不完整。** 最新协议已烧录，八页静态画面留证；音乐实播、宠物连续动画、提醒/闹钟、传感器接线和长期 PSRAM 行为仍需专项验收，不能把“静态画面正常”写成“已交付”。
2. **产品闭环仍有平台边界。** macOS 的媒体、系统通知、日历权限需要在最终 `.app` 身份下验证；CLI Python 的授权结果不能代表正式应用包。
3. **资源预算要看运行时峰值。** 固件占用约 70.3% 分区，仍有空间；JPEG 皮肤的 PSRAM/LRU 抖动必须以切帧耗时、剩余 PSRAM 和长时间互动验证，不能只看静态大小。
4. **文档边界曾与用户决策冲突。** `产品愿景与范围边界_v1.md` 仍是草案，其中“一概不做系统闹钟/外部日历”不能覆盖已实现的设备闹钟和用户此前提出的日程需求。本路线图按用户已表达的优先级推进。
5. **构建有一个手势宏重复定义警告。** `LV_INDEV_DEF_GESTURE_LIMIT` 在项目配置为 30、LVGL 头文件又定义为 50；编译可过，但最终阈值应在真机滑页验收时确认并统一。

## 4. 下一步顺序与完成标准

### M0：新固件真机基线（先做）

- 烧录当前构建，记录 FW/CAPS 握手、CFG 应用版本、10 页导航、各页面照片与串口错误。
- 分别验证内置矢量宠物和已装 JPEG 皮肤：眨眼/工作/喂食/喝水/运动连续动作，无串页、缺帧或明显卡顿；记录 `PETPERF` 加载耗时及剩余 PSRAM。
- 同屏核对音乐、模型用量、多城市天气、活动提醒和传感器缺失状态。
- **完成标准：** 每项有照片或日志、复现步骤、通过/失败结论；失败项先修复再进入 M1。

### M1：状态一致性与单一应用闭环

- 选一款用户实际使用的音乐软件，完成“发现会话 → 控制 → 电脑状态变化 → 屏幕 1 秒内回显 → 无会话时明确提示”的手测闭环。
- 对 AI 来源显示读取能力、数据时间戳与失败原因；抽取实际会话核对任务、模型和 Token 口径。
- 对 Web 保存、设备应用回执、重启恢复和断连重连增加同一配置版本的端到端记录。
- **完成标准：** 连续日常使用一轮，关键读数与电脑一致；每个失败状态有用户可理解的提示。
- **进展（2026-10-16）：** 第 2、3 条的可代码部分已实现——(3) 保存/下发/设备回执/断连重连统一写入 `config_trace` 内存环，`/api/status` 暴露、Web 自检显示「保存→下发→设备」版本链路与一致态，重连保留 `applied_version`（版本一致则不重推全量配置、不闪「待同步」）；(2) 新增 `ai_sources`：逐来源给出读取方式 / 根目录 / 活跃会话数 / 最近数据时间戳 / 失败原因，Web 自检逐来源显示。剩余为**纯真机手测**：选一款真实音乐软件连测 15 分钟闭环、抽原始会话日志核对 Token/模型口径。

### M2：页面编辑与日程闹钟

- 合并散落的屏幕配置入口，围绕“选组件 → 排页面 → 预览 → 保存 → 真机回执”形成一条路径；优先修复大/小卡、长文本和超过 6 页导航。
- 完成设备闹钟稍后、跨日、断连恢复；完善日程来源和全天/跨天显示。系统日历以用户授权后的实测为准。
- **完成标准：** 用户不改代码即可完成页面和提醒配置，真机内容与预览一致。

### M3：趋势、硬件告警与自动化

- 在数据来源可信后增加持续高温、风扇异常、设备断连/数据陈旧告警；使用持续时间、恢复事件和可调阈值，避免瞬时噪声。
- 趋势与自动化只读取已验证指标，规则需要冷却时间和清晰的撤销路径。
- **完成标准：** 告警能解释依据、可处理、可恢复，且不会连续刷屏。

### 发布前独立门槛

- macOS `.app` 的原生二进制、日历/通知权限、签名与安装说明；Windows 不以未实测能力对外宣传。
- OTA、配置回滚、资源包损坏与断电恢复做一次完整回归。

## 5. 暂缓范围

遵循用户此前确定的顺序：**状态一致性 → 单一应用闭环 → 合并屏幕编辑 → 日程闹钟完整流程 → 趋势与自动化**。先暂停继续扩充主题、高清宠物种类和本地操作历史。已有宠物狗与像素宠物可以继续打磨动作；真实步数需未来有可信的随身数据源，当前只做活动与休息提醒。

本路线图不再用“待用户批准产品定位”阻塞上述已授权的质量工作。新功能是否加入，以真实使用问题、数据来源、设备性能和验收成本判断。

### 6.2 固件 I²C 引脚改线（需重烧，影响传感器验收）
- `config.h`：三传感器 I²C 从 **GPIO47/48 改为真实硬件接线 GPIO1/2**（`SDA→1`、`SCL→2`）；`sensors.h` 改为按配置引脚并自动探测反接方向；`main.cpp` 在握手时补发一次 `SN` 诊断；`README.md` 同步说明 GPIO1/2 已不能作 LED。
- ⚠️ **关键影响**：M0 基线烧录用的是旧引脚（47/48）。**在真实硬件上验证 AHT20/BMP280/VL6180X 前，必须先用 GPIO1/2 配置重新 `pio run -t upload`**，否则 I²C 扫描扫不到设备，`ENVSRC` 会回退 `NA`，§2「天气与传感器」的真机读数验收将无效。
- 建议把"按 GPIO1/2 重烧 + 传感器读数验收"列为 M0 收尾的第一子项。
