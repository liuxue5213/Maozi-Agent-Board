# 下一里程碑：页面自定义与提醒组件

状态：设计稿，尚未实现。目标是让用户在 Web 设置页完成页面数量、组件排列、提醒、日历和闹钟配置，无需修改代码。

## 1. 交付范围

- 客户端提供本机 Web 设置页：增删和拖排页面，选择 2×2 网格或列表布局，勾选并排序组件，录入提醒、今日日历事件和闹钟，实时预览及校验。
- 客户端保存配置版本，经 `CFG` 分段推送；设备校验、应用并回报版本。离线时可保存草稿，连接后再同步。
- 固件按页面清单建立插槽，渲染 `ai_list`、`clock`、`hw_cards`、`environment`、`reminder_list`、`today_calendar`、`alarm`。左右滑动和可见页码导航均能切页。
- 闹钟到点在设备上闪烁提示并让背光呼吸；用户触摸可停止当次提示。配置、传输和设备应用的结果分别显示，不能把“已发送”当成“已生效”。

本期日历事件和提醒由用户在设置页手动录入；外部日历同步、通知推送和电脑端系统闹钟不在本期范围。

## 2. 配置模型

`pages[].widgets` 保持按显示顺序排列的组件类型列表。页面 `id` 用于拖排后保持身份；布局由 `layout` 决定，插槽位置由列表顺序自动分配，用户不必编辑坐标。

```json
{
  "schema": 1,
  "version": 12,
  "timezone": "Asia/Shanghai",
  "pages": [
    {"id": "work", "title": "工作", "layout": "list", "widgets": ["ai_list"]},
    {"id": "system", "title": "电脑", "layout": "grid_2x2", "widgets": ["hw_cards"]},
    {"id": "today", "title": "今天", "layout": "grid_2x2", "widgets": ["today_calendar", "reminder_list"]},
    {"id": "desk", "title": "桌面", "layout": "grid_2x2", "widgets": ["environment", "alarm", "clock"]}
  ],
  "reminders": [
    {"id": "r1", "time": "09:30", "text": "站会", "weekdays": [1, 2, 3, 4, 5], "enabled": true}
  ],
  "calendar": [
    {"id": "e1", "date": "2026-10-09", "time": "14:00", "title": "方案评审"}
  ],
  "alarms": [
    {"id": "a1", "time": "18:00", "label": "休息", "weekdays": [1, 2, 3, 4, 5], "enabled": true}
  ]
}
```

日期用设备所在时区的 `YYYY-MM-DD`，时间用 24 小时 `HH:MM`，`weekdays` 为周一 `1` 至周日 `7`；空数组表示仅指定日期执行，需配 `date`。提醒仅在列表中显示，不触发灯光；闹钟才触发闪烁和背光呼吸。日历事件只显示当天条目，跨天后自动刷新。

能力由设备握手回报，客户端按实际能力校验，不将这里的示例数量视为硬件承诺。首版建议上限：1–6 页、每页最多 4 个组件、提醒 20 条、日历未来 30 天内 50 条、闹钟 16 条、标题按实际字体覆盖及像素宽度限制。限制以真机内存和可读性测试冻结。

## 3. 插槽与组件规则

`grid_2x2` 为四个单元格，组件按列表顺序从左上到右下填充。`list` 为纵向列表，按顺序分配行高，超出屏幕时在设置页报错，不在设备上静默截断。组件声明最小尺寸；`ai_list` 和 `hw_cards` 占整页，不能与其他组件同页。`reminder_list`、`today_calendar` 默认占一整行，其余组件占一个网格单元。预览和设备共用同一套占位、文本截断及字体规则。

空内容有明确表现：无 AI 任务显示“暂无任务”；无今日日程显示“今天无日程”；无提醒或闹钟显示“未设置”；传感器、电脑指标和日历时间不可用时显示“数据不可用”及最近有效时间。页面删除后至少保留一页；删除当前页时切到相邻页。

## 4. Web 设置页

页面分为四区：页面列表（新增、删除、拖排）、组件选择与布局、提醒／日历／闹钟表单、设备预览及同步状态。选择组件后立即预览，保存前校验页数、插槽冲突、文字溢出、日期时间、重复 `id`、资源预算。提供恢复默认布局和取消未保存修改。

状态依次为：`草稿 → 已保存 → 待同步 → 传输中 → 设备已应用`；失败显示具体原因和重试按钮。用户编辑草稿不影响设备上的上一有效配置。设置页仅监听 `127.0.0.1`，不把日志正文、会话内容或外部服务凭证放入配置文件或发给设备。

## 5. CFG 同步契约

沿用现有文本串口链路和 `CFG` 前缀，新增配置事务；旧的 `CFG=bg:...,bright:...` 保留用于即时主题／亮度设置。配置 JSON 用 UTF-8 编码后分段，避免超过固件目前 191 字节的单行缓冲区：

```text
CFG=BEGIN,12,3456,89ABCDEF
CFG=DATA,12,0,<base64-of-up-to-90-raw-bytes>
CFG=DATA,12,1,<base64-of-up-to-90-raw-bytes>
CFG=END,12
ACK=CFG,12,APPLIED
NAK=CFG,12,CRC_MISMATCH
```

`BEGIN` 包含版本、UTF-8 字节数和 CRC32；`DATA` 序号从 0 连续递增，每行原始载荷最多 90 字节；`END` 后设备校验长度、CRC、schema、组件支持和布局，再保存到非活动配置槽并切换。仅收到 `ACK=...,APPLIED` 后，客户端才显示“设备已应用”。失败保留上一有效配置。断线或超时丢弃未完成事务；重连后客户端重新发送当前已保存版本。遥测与配置事务可交错，但设备必须按 `version + seq` 组包。

设备上报 `FW` 时同时提供 `schema`、支持的组件和容量；客户端不得向不兼容固件推送配置。建议在协议升级为 v0.3 时，把字段和错误码写入 `PROTOCOL.md` 并做双端测试。

## 6. 日期、闹钟与失联

客户端在连接、跨天、系统时间或时区变化时推送完整本地日期时间与时区；现有 `TIME=HHMMSS` 可继续驱动时钟，但不足以判断“今日日历”和每周闹钟。设备用最近一次同步时间加 `millis()` 维持短时离线时钟，显示“时间未同步”或“时间可能不准”，不假装仍与电脑一致。设备重启后未取得有效日期时间前不触发闹钟。

闹钟以 `alarm id + 本地日期` 去重，同一分钟只触发一次；触发时显示标签、屏幕闪烁及背光呼吸，触摸“停止”结束当次动画，不删除规则。重连、页面切换或配置重发不得重复触发。动画期间限制亮度范围并允许关闭动效；无触摸时按设置的超时自动停止，随后恢复用户亮度。

## 7. 验收

1. 用户在设置页增删、拖排页面和组件并保存，设备应用回执后显示与预览一致；不需要改代码。
2. 离线编辑、传输中断、配置非法、设备重启后均保留上一有效配置；状态和错误原因可见。
3. 同一天多条日程、无日程、跨天、时区变化和时间未同步均显示正确状态。
4. 闹钟只在符合日期／星期的时间触发一次；触摸停止、超时停止、断线重连均不会重复触发，亮度能恢复。
5. 组件无数据、数据过期和页面内容过多时有明确空态或校验错误，不显示旧值为实时值。
