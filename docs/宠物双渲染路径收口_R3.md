# 宠物双渲染路径收口（R3）

> 起草：2026-10-16 · 关联：`docs/产品愿景与范围边界_v2.md` 决策 2 · `docs/AI_PIXEL_PET_DESIGN.md` · `docs/宠物包资产管线_v1.md`
> 结论：**矢量 `draw_pet` 为 canonical，JPEG 皮肤为可选 —— 此项已在固件代码中落地，本文件确权 + 列残留清理成本。**

---

## 1. 拍板结论

**canonical = 矢量 `draw_pet`；JPEG 角色包 = 可选皮肤。** 该决策不是纸面方案，而是**已在固件代码实现的现状**。维护双路径的代价可控，不建议删除 JPEG 路径（否则丧失"可选拟真皮肤"卖点）。

---

## 2. 代码事实（引证）

| 位置 | 事实 |
|---|---|
| `firmware/src/ui.cpp:1368` | 注释明确："矢量 `draw_pet` 为 canonical（内置、零 PSRAM、永远可用）；`/pet_<帧>.jpg` 资源包是「可选皮肤」，仅当客户端按 day/night/weather 上传后才存在" |
| `firmware/src/ui.cpp:1399` | `make_pet_page` **始终创建**矢量 `draw_pet` 部件（`draw_pet(visual.parts, screen, g_profile.pet_type, 96, 66, 2)`） |
| `firmware/src/ui.cpp:1382-1405` | 图源优先级：`custom 形象 > 状态帧图集 > 矢量回落`；无皮肤时矢量部件显隐切换 |
| `firmware/src/ui.cpp:1607-1649` | `render_pet_page`：先按当前层取皮肤帧名，`petimg_exists` 不存在 → 走 `else` 分支显示矢量（`visual.parts.root` 取消隐藏） |
| `firmware/src/bgimg.cpp:18` | 注释："矢量 `draw_pet` 为 canonical… 皮肤仅在包被上传后才解码" |

**渲染路由逻辑（已落地）：**
```
有 pet_custom.jpg        → 显示 custom 形象（最高优先）
有 pet_idle/pet_working  → 显示状态帧图集（JPEG 皮肤）
两者皆无                → 矢量 draw_pet 回落（永远可用，零 PSRAM 大块占用）
```
触摸场景缺专属帧时回退（`feeding/drinking→greeting`、`playing→working`），整包不完整回落矢量。

## 3. 与 `AI_PIXEL_PET_DESIGN.md` 的对齐

- 该设计文档 §8 设想"精灵表（Sprite Sheet）"路线；**实际落地为程序化矢量部件**（LVGL rect + `lv_anim`），零美术资产、PSRAM 友好，状态机接口不变。
- §8 的 sprite sheet 路线**降级为未来可选升级路径**，不阻塞当前实现。
- ⚠️ **文档债**：`AI_PIXEL_PET_DESIGN.md` §8 与 §11 的"落地状态"已注明实际为矢量，但 §4-§8 仍大量描述精灵表细节。建议在该文头部加一条醒目注记："当前实现为程序化矢量 `draw_pet`，精灵表为可选升级，状态机接口不变"，避免后人误判现状。
