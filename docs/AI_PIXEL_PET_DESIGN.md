# AI 像素电子宠物交互系统设计文档

> 版本：v1.0 · 起草：2026-10-10 · 适用：桌面伴侣设备（ESP32-S3 + LVGL / Python 客户端）及桌面悬浮窗

---

## 1. 系统概述

AI 像素电子宠物（以下简称「宠物」）是一个**状态驱动**的桌面伴侣角色。它以像素美术风格呈现，实时反映「AI 会话活动」与「系统时间」两大信号，并通过动画与表情与用户建立情感连接。

### 1.1 设计目标
- **状态可视**：把抽象的 AI 工作状态（奋笔疾书 / 闲置发呆 / 犯困睡觉）转化为可被一眼读懂的像素动画。
- **时间共感**：随系统时间自然切换昼夜节律，深夜自动进入犯困 / 睡觉状态。
- **双形态一致**：同一套状态机、动画与逻辑，既能作为**首屏主体**，也能作为**悬浮标签**，仅尺寸与细节密度不同。
- **零侵入**：宠物不阻断主业务，悬浮形态始终是「可忽略的背景层」。

### 1.2 形态定位
| 形态 | 角色 | 尺寸档 | 背景 | 文案 | 典型位置 |
|------|------|--------|------|------|----------|
| 首屏主体 | 主视觉焦点 | 大（如 240×240 / 全屏） | 有场景背景 | 名称 + 状态句 | 设备主屏 / 客户端首页 |
| 悬浮标签 | 常驻伴随 | 小（如 64×64 / 96×96） | 无背景（透明） | 仅图标/微表情 | 屏幕角落 / 桌面悬浮窗 |

> **核心约束**：两种形态**共用同一状态机与动画脚本**，仅通过「尺寸档位 + 细节密度」参数做降采样。功能与触发规则完全一致。

## 2. 核心交互逻辑（必须保留）

无论形态如何，以下主循环逻辑是系统的骨架，**不可删改**：

```
┌─────────────┐    ┌──────────────┐    ┌────────────┐    ┌──────────────┐
│ 感知层       │ →  │ 状态仲裁层    │ →  │ 渲染层      │ →  │ 形态适配层    │
│ Sense        │    │ Arbitrate    │    │ Render     │    │ Adapt        │
└─────────────┘    └──────────────┘    └────────────┘    └──────────────┘
   │ 信号源              │ 优先级覆盖             │ 动画/表情           │ 大/小尺寸
   ├ AI 活动(aiwatch)   ├ 时间层(SLEEPY/SLEEP)  ├ 精灵帧序列          ├ 主屏：完整帧
   ├ 系统事件(完成/错误) ├ 活动层(WORKING/IDLE)  ├ 表情参数            └ 悬浮：精简帧
   └ 系统时钟(时分)     └ 场景层(瞬时覆盖)       └ 调色/特效
```

1. **感知层**：采集 AI 会话状态（来自 aiwatch：working / wait_input / error）、系统事件（任务完成 / 异常）、系统时钟（HH:MM）。
2. **状态仲裁层**：按 §4 的优先级规则，把多路信号合并为**唯一当前状态**。
3. **渲染层**：根据当前状态加载对应动画脚本（帧序列 + 表情参数 + 调色）。
4. **形态适配层**：按尺寸档位做精灵降采样与细节裁剪，保证大/小形态表现同源。

> ⚠️ 任何形态切换、新增场景、新增状态，**不得破坏**感知→仲裁→渲染→适配这条链路。

## 3. 状态机定义

### 3.1 状态总览
系统状态分为三层：**活动层（Activity）**、**时间层（Temporal）**、**场景层（Scene，瞬时覆盖）**。常态由「活动层 + 时间层」决定，场景层以有限时长覆盖其上。

| 状态 ID | 名称 | 所属层 | 触发来源 | 是否常态 |
|---------|------|--------|----------|----------|
| `WORKING` | 奋笔疾书 | 活动层 | AI 正在生成/工作 | 是 |
| `IDLE` | 无聊发呆 | 活动层 | 无活动 ≥ 阈值 | 是 |
| `THINKING` | 托腮思考 | 活动层 | AI 等待/短暂停顿 | 是（过渡） |
| `SLEEPY` | 犯困 | 时间层 | 深夜时段（软覆盖） | 是（夜间） |
| `SLEEPING` | 睡觉 | 时间层 | 凌晨时段（硬覆盖） | 是（凌晨） |
| `GREETING` | 问候唤醒 | 场景层 | 启动 / 整点问候 | 否（瞬时） |
| `CELEBRATE` | 完成任务 | 场景层 | 任务完成事件 | 否（瞬时） |
| `ALERT` | 异常提醒 | 场景层 | 错误 / 超时事件 | 否（瞬时） |
| `PLAYING` | 互动玩耍 | 场景层 | 用户点击/逗弄 | 否（瞬时） |

### 3.2 状态转移规则
- **活动层内**：`IDLE ⇄ THINKING ⇄ WORKING`，由 AI 会话状态实时切换，无最小停留（但渲染层需做 200ms 防抖，避免抖动）。
- **时间层覆盖**：夜间 `SLEEPY` / `SLEEPING` 由系统时钟驱动；凌晨 `SLEEPING` 为**硬覆盖**（除非发生 `CELEBRATE`/`ALERT` 高优事件）。
- **场景层覆盖**：`GREETING`/`CELEBRATE`/`ALERT`/`PLAYING` 以「持续时间」或「事件解除」结束，结束后回退到活动层/时间层基态。
- **优先级（高→低）**：`ALERT` > `CELEBRATE` > `PLAYING` > `GREETING` > 时间层(`SLEEPING`>`SLEEPY`) > 活动层(`WORKING`>`THINKING`>`IDLE`)。

### 3.3 状态机图

```
            ┌──────────── 系统时钟 ────────────┐
            │ 22:00-01:00        01:00-06:00   │
            ▼                  ▼                │
   ┌─── IDLE ───┐      SLEEPY ──────► SLEEPING │
   │   (发呆)   │         (犯困)       (睡觉)  │
   └──┬───┬────┘            ▲            │      │
      │   │ AI working      │ 时间离开   │ 时间离开
      │   ▼                 │ 夜间窗口   │ 凌晨窗口
      │  WORKING            └────────────┘      │
      │   (疾书)                                 │
      │   ▲                                     │
      │   │ AI wait_input                        │
      │  THINKING                               │
      │   (思考)                                 │
      └─────────────────────────────────────────┘
                场景层瞬时覆盖（任意基态之上）：
        GREETING ⇄ PLAYING ⇄ CELEBRATE ⇄ ALERT
        （结束/事件解除后回退到上方基态）
```

## 4. 各状态视觉表现

> 像素规格以「基准 32×32 精灵网格」描述；悬浮形态按 §7 降采样。表情参数指眼睛/嘴/附加物的可变量。

### 4.1 `WORKING` — 奋笔疾书
- **构图**：宠物坐于小桌前，面前一叠纸，右手持笔。
- **动画（8 帧循环，~12fps）**：
  - 手臂高频上下摆动（笔尖在纸上快速点画）。
  - 纸上逐帧出现墨迹短划（3 帧后出现、循环保留）。
  - 头部随书写轻微左右晃动。
  - 额角偶现「汗滴」像素（每 4 循环 1 次）。
- **表情**：眼睛专注前视（半睁），嘴角微抿；眉梢微挑显投入。
- **调色**：主色保持主题强调色；笔尖高亮白。
- **附加**：状态句「正在为你写代码…」（仅首屏）。

### 4.2 `IDLE` — 无聊发呆
- **构图**：宠物抱膝坐地 / 趴桌，眼神放空。
- **动画（6 帧循环，~6fps，慢）**：
  - 缓慢眨眼（每 2 循环闭眼 1 帧）。
  - 头偶尔歪向一侧，出现「…」气泡上飘。
  - 脚尖无意识点地（2 帧交替）。
  - 长时间无活动后（≥30s）加入打哈欠（张口 1 帧）。
- **表情**：眼睛半圆放空、瞳孔上飘；嘴小圆「o」或平线。
- **调色**：整体略降饱和，显慵懒。
- **附加**：状态句「在等你呢～」（仅首屏）。

### 4.3 `THINKING` — 托腮思考
- **构图**：一手托腮，另一手指点太阳穴。
- **动画（4 帧，~8fps）**：头部微倾 + 头顶「？」气泡闪烁；偶尔换成「💡」表示有思路。
- **表情**：眼睛斜视上方，嘴微抿。
- **用途**：AI 处于 `wait_input` 或短暂停顿时，避免误显 `IDLE` 的「被遗忘感」。

### 4.4 `SLEEPY` — 犯困
- **构图**：宠物揉眼 / 点头，身形微晃。
- **动画（6 帧，~5fps）**：眼皮半垂（逐帧下垂）；身体左右轻摇（似随时入睡）；「Z」气泡小而上飘。
- **表情**：眼睛成「︶ ︶」弧线半闭，嘴微张打呵欠。
- **调色**：叠加暖暗滤镜（画面整体压暗 15%）。
- **触发**：系统时间进入 22:00–01:00，且活动层为 `IDLE`/`THINKING`。

### 4.5 `SLEEPING` — 睡觉
- **构图**：宠物蜷缩，闭眼，身下小褥子。
- **动画（4 帧，~4fps，极慢）**：腹部呼吸缩放（±2px 周期 2s）；「Z Z Z」依次上飘循环。
- **表情**：眼睛闭（─ ─），嘴小弧。
- **调色**：深暗夜色滤镜（压暗 35%、偏蓝）。
- **硬覆盖**：01:00–06:00 强制进入，除非 `ALERT`/`CELEBRATE` 高优事件打断（打断后恢复 `SLEEPING`）。

### 4.6 `GREETING` — 问候唤醒
- **触发**：客户端启动、或整点/半点问候（可配置）。
- **动画（5 帧，~10fps）**：宠物蹦跳 + 挥手；头顶「！」或气泡「嗨～」。
- **时长**：3s 或用户交互后结束。
- **时间文案**：早安（06–09）/ 午安（11–14）/ 晚安（20–23）。

### 4.7 `CELEBRATE` — 完成任务
- **触发**：AI 会话 `completed` / 任务成功事件。
- **动画（8 帧，~12fps）**：跳跃 + 双臂上举；周围迸发像素星星/彩屑（程序化粒子）。
- **表情**：眼睛弯月「^ ^」，大笑嘴。
- **时长**：4s 或下一活动开始。

### 4.8 `ALERT` — 异常提醒
- **触发**：AI `error` / 超时 / 连接断开。
- **动画（4 帧，~8fps，抖动）**：身体左右急颤；头顶「！」红色闪烁。
- **表情**：眼睛瞪大「◎ ◎」，嘴张「O」。
- **调色**：局部红色脉冲（不破坏整体主题，仅警示物红）。
- **时长**：持续到事件解除或 6s 上限。

### 4.9 `PLAYING` — 互动玩耍
- **触发**：用户点击/逗弄宠物（悬浮形态可点，首屏可戳）。
- **动画（6 帧，~12fps）**：原地转圈 / 抛接小球 / 蹦跳。
- **表情**：开心眯眼，吐舌。
- **时长**：互动期间；停止交互 2s 后回退基态。

## 5. 场景系统

场景 = **背景 + 动作集 + 表情集 + 氛围特效** 的可组合单元。宠物在不同场景下复用同一状态机，但视觉语境不同。

| 场景 ID | 名称 | 背景 | 专属动作/特效 | 适用形态 |
|---------|------|------|---------------|----------|
| `SCENE_DESK` | 书桌 | 木桌+台灯+纸堆 | 书写光晕、咖啡杯热气 | 首屏主体 |
| `SCENE_NIGHT` | 夜晚 | 月窗+星点+褥子 | 萤火微光、Z 气泡 | 双形态 |
| `SCENE_PARK` | 草地 | 草地+云+太阳 | 蝴蝶飞过、花朵摇摆 | 首屏主体 |
| `SCENE_SPACE` | 太空 | 星海+行星 | 失重漂浮、流星 | 首屏主体 |
| `SCENE_MINI` | 极简 | 纯色/透明 | 无背景，仅宠物+微表情 | 悬浮标签 |

- **场景切换规则**：默认 `SCENE_DESK`；时间层进入 `SLEEPY`/`SLEEPING` 自动叠加 `SCENE_NIGHT` 氛围；悬浮形态恒为 `SCENE_MINI`。用户可在设置页手动锁定场景。
- **动作/表情一致性**：同一状态（如 `WORKING`）在 `SCENE_DESK` 是「伏案书写」，在 `SCENE_SPACE` 是「悬浮操作控制台」——动作外壳不同，**但「高专注 + 快速手部运动」的核心语义不变**。

## 6. 时间触发规则

系统时钟（来自宿主机的本地时间 `HH:MM`）驱动时间层，并与活动层仲裁。

### 6.1 时段表
| 时段 | 时间窗 | 基态倾向 | 场景叠加 | 备注 |
|------|--------|----------|----------|------|
| 清晨 | 06:00–09:00 | `GREETING`(启动/整点) → `IDLE` | 晨光滤镜 | 早安问候 |
| 日间 | 09:00–18:00 | `WORKING`/`THINKING`/`IDLE` | `SCENE_DESK` | 正常活动窗口 |
| 傍晚 | 18:00–22:00 | 同上，节奏略缓 | 暖橙滤镜 | 可降帧省电 |
| 深夜 | 22:00–01:00 | `SLEEPY`（覆盖 `IDLE`/`THINKING`） | `SCENE_NIGHT` | 软覆盖 |
| 凌晨 | 01:00–06:00 | `SLEEPING`（硬覆盖） | `SCENE_NIGHT` | 除非高优事件 |

### 6.2 深夜犯困 / 睡觉的仲裁细节
- **22:00–01:00（SLEEPY，软覆盖）**：若 AI 处于 `WORKING`，则**不强制犯困**，保留 `WORKING`（即「陪你熬夜干活」）；一旦 AI 回到 `IDLE`/`THINKING` 且持续 ≥10s，转入 `SLEEPY`。
- **01:00–06:00（SLEEPING，硬覆盖）**：强制 `SLEEPING`；若此时发生 `CELEBRATE`/`ALERT`，临时切到该高优状态，事件结束后**立即恢复 `SLEEPING`**。
- **唤醒**：06:00 整点或用户首次交互，触发 `GREETING`(早安) 后回退正常基态。
- **可配置项**：用户可在设置关闭「自动睡眠」，改为仅 `SLEEPY` 提示而不强制 `SLEEPING`。

### 6.3 整点问候
- 每个整点/半点（可关）触发一次 `GREETING`，文案随 §6.1 时段变化，不与深夜/凌晨睡眠冲突（凌晨不问候，保持安静）。

## 7. 两种形态规格

| 参数 | 首屏主体 | 悬浮标签 |
|------|----------|----------|
| 精灵基准 | 32×32（渲染放大至 240×240） | 32×32（渲染至 64×64 / 96×96） |
| 帧率 | 全帧率（如 12fps） | 降帧（6–8fps）以省资源 |
| 背景 | 有（场景背景） | 无（透明，`SCENE_MINI`） |
| 状态句文案 | 显示 | 隐藏（仅图标/微表情） |
| 交互 | 可戳互动（`PLAYING`） | 可点互动（`PLAYING`） |
| 粒子特效 | 完整（星星/彩屑/汗滴） | 精简（仅关键 1–2 像素） |
| 调色滤镜 | 完整（昼夜压暗） | 同逻辑，但仅作用于宠物本体 |
| **共用** | **同一状态机、同一动画脚本、同一触发规则** | **同上** |

> 实现要点：动画脚本以「逻辑帧 + 参数」描述，**渲染器**按形态档位决定放大倍数、是否绘制背景与文案、是否降帧。逻辑与表现解耦，保证「功能一致、仅尺寸不同」。

## 8. 像素动画技术规范（落地建议）

- **精灵表（Sprite Sheet）**：每状态导出一张横向帧序列 PNG（如 `working_8f.png`，32×32×8）。悬浮形态复用同一张表，仅渲染时缩小。
- **帧率与防抖**：活动层切换加 200ms 防抖；时间层切换加 1s 迟滞，避免跨时段边界抖动。
- **程序化特效**：汗滴、Z 气泡、星星等用轻量粒子（位置+生命周期），不进精灵表，降低资源。
- **LVGL 端（设备）**：用 `lv_img` 序列或 `lv_canvas` 逐帧绘制；`SLEEPING` 呼吸用 `lv_obj_set_style_transform_scale` 周期 tween。
- **Python 客户端（悬浮窗）**：用 `pygame`/`PIL` 或系统托盘图标帧动画；透明窗口承载 `SCENE_MINI`。
- **状态句文案**：首屏用 `lv_label`；悬浮形态不渲染，避免遮挡。
- **资源预算**：全部精灵表合计建议 ≤ 64KB（PSRAM 友好），优先复用共用帧（如眨眼帧跨状态共用）。

## 9. 与现有桌面伴侣的集成建议

- **活动感知**：直接复用 `aiwatch` 已有的四来源会话状态（`working`/`wait_input`/`error`/`completed`），映射为 `WORKING`/`THINKING`/`ALERT`/`CELEBRATE`。
- **系统时钟**：Python 客户端读取宿主机本地时间；设备端由客户端经 CFG 下发当前 `HH:MM`（或设备自身 RTC）。
- **设置页**：在现有 Web 设置页新增「宠物」分区——场景锁定、自动睡眠开关、问候开关、形态选择（首屏/悬浮）。
- **零侵入**：悬浮形态作为独立常驻层，不占用原有状态卡片布局。

## 10. 待确认 / 开放决策点

1. **深夜强睡 vs 陪熬**：01:00–06:00 是否允许「AI 在干活就不睡」？本文默认**硬覆盖强制睡**，但可改为软覆盖（见 §6.2）。
2. **悬浮形态默认开关**：是否开机即悬浮，还是仅首屏？建议默认首屏，用户可切悬浮。
3. **宠物人设**：像素角色物种/名字（猫/精灵/机器人）需在美术阶段定稿，影响精灵表产出。
4. **音效**：是否加入 8-bit 音效（书写沙沙、睡觉 Z 声），受设备扬声器约束。

## 11. 落地状态（2026-10-10 深夜实现）

### 已落地（固件实拍验证）

- **三层仲裁状态机**：`firmware/src/ui.cpp` 的 `pet_arbitrate()`——优先级 ALERT > CELEBRATE > PLAYING > GREETING > SLEEPING(硬) > SLEEPY(软) > WORKING > THINKING > IDLE，与 §3.2 一致。
  - 时间层读设备本地时钟（客户端 TIME= 下行的 HHMMSS）；SLEEPY 22:00–01:00 软覆盖带 10s 迟滞，AI 在干活则「陪你熬夜」；SLEEPING 01:00–06:00 硬覆盖（CELEBRATE/ALERT 可临时打断，到期即恢复）。
  - 场景层：ERROR→ALERT(6s)、DONE→CELEBRATE(4s)、开机 GREETING(3s，凌晨 1–6 点不打扰)、客户端「运动」互动→`PET=play` 下行→PLAYING(2.5s)。
- **九状态视觉**（矩形像素宠物演绎，`pet_apply_expression`）：眼高/视线偏移/嘴宽/徽标/摇摆节奏按状态切换——WORKING 睁眼、THINKING 眼上移+「?」、IDLE 半睁慢摇、SLEEPY 眯眼+「Z」、SLEEPING 闭眼呼吸+「z」、GREETING「嗨」+起跳、CELEBRATE 弯眼大笑+双跳、PLAYING 眯眼、ALERT 红眼红框+抖动。眨眼动画由表情层统一接管（先删后建）。
- **饿渴累徽标**只在活动层显示（睡觉/场景进行时不多嘴）。
- **预览镜像**：工作台 `devPet` 内置同一套仲裁与视觉表，预览=实机。
- 测试 302 全绿（新增 PET=play 转发用例）。

### 实现口径与 §8 的差异

- 动画采用**程序化矩形部件**（LVGL rect + lv_anim）而非精灵表——与现有宠物画法同源，零美术资产；
  §8 的 sprite sheet 路线保留为后续升级路径，状态机接口不变。
- 形态适配：当前两档尺寸（AI 卡紧凑体 sz=1 / 宠物页大只 sz=2）共用同一状态机，即 §7「双形态同源」。
