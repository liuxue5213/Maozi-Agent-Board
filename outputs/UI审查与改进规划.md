# maozi-diy 触控屏 UI 全面检查与改进规划

日期：2026-10-09｜ 输入：3 张实机照片（环境页 / 电脑页 / AI 工作台页）+ `firmware/src/ui.cpp`、`profile.py`、`display.cpp`、`config.h`
方法：照片实测比例 ↔ 代码几何常量逐项核对，所有像素与对比度数值均可复现

---

## 0. 核心结论

三张照片暴露的不是"审美偏好"问题，而是**四类可定位的结构性缺陷**。其中两项我已在代码中定位到具体行号：

| # | 问题 | 实测证据 | 代码根因 |
|---|---|---|---|
| 1 | **卡片边界几乎不可见** | 照片中卡片与背景仅靠极轻微色差区分，实测对比度 **1.12:1**（屏幕下半部渐变处 **1.03:1**），WCAG 对非文本组件要求 ≥3:1 | `config.h:29` `COL_CARD 0x141E32` 与 `COL_BG 0x0B1220` 亮度过近 |
| 2 | **大量死区** | 环境页 43% 屏幕（206px）完全空白；AI 页卡片内 270px 空洞 | `make_generic`/`make_ai` 用固定 y 偏移 + 固定 190px 卡高，不按内容或实际组件数分配 |
| 3 | **触控热区过小** | 底部页码圆点 **34×24px**，低于 44×44 最小可触标准；间距计算与实际不符 | `ui.cpp:361` `box(..., x0 + k*40, FOOT_Y, 34, 24)` |
| 4 | **字体层级倒挂** | 照片中"等待编辑器活动"（次要状态）比"暂无活跃会话"（主要状态）更大更醒目 | `ui.cpp:230-231` main 用 20px、sub 用 32px |

**优先级判断：1 和 2 是必须先修的**——它们让屏幕在真实摆放距离下"看不出哪里是内容、哪里是空白"，直接抵消了产品"一眼看懂"的核心承诺。

## 1. 当前界面结构与布局方式

### 1.1 整体框架（所有页面共用）

代码中的固定几何常量（`ui.cpp:14-20`）：

```
SCR_W=320  SCR_H=480          竖屏，ST7796 native
HEAD_Y = 8                   标题行基线
BODY_Y = 56                  内容区顶
BODY_H = 390                 内容区高（56..446）
FOOT_Y = 452                 页码行
EDGE_TOP = 90/ EDGE_BOTTOM = 390   （声明但未使用，见5.4）
```

页面结构自上而下分四层：

| 层 | y 范围 | 内容 | 实现 |
|---|---|---|---|
| 标题层 | 8~46 | 页面标题 + 连接状态 + 操作提示 | `label()` 直接绝对定位 |
| 内容层 | 56~446 | 组件网格 | `make_ai` / `make_hardware` / `make_generic` |
| 页码层 | 452~476 | 页码圆点 | `build_page` 尾部循环 |
| 覆盖层 | 全屏 | 启动器 / 控制中心 / 闹钟 | 独立 screen + `lv_scr_load_anim` |

### 1.2 各功能区域的布局方式

**A. AI 工作台页（`make_ai`，独占整页）**

```
8,56,304,390  单张满页卡片
├── (12,10)  main   20px  ← "暂无活跃会话"   主状态
├── (12,44)  sub    32px  ← "等待编辑器活动"  次状态（字号更大！）
├── (12,96)  extra  16px  ← "Claude Code / Codex / ZCode"
└── 3 个任务行 284×56，y = 140 + 64*i，隐藏/显示随任务数
```

**B. 电脑页（`make_hardware`，2×2 实占满屏）**

```
每卡 148×190，(8 + (i%2)*156, 56 + (i/2)*196)
├── (10,10)  标题   16px  处理器/内存/显卡/磁盘
```

**C. 通用组件（`make_generic`，list 与 grid_2x2 两种）**

```

```

**D. 覆盖层**

- 启动器：3 列网格，96×90，间距 102×100
- 控制中心：三组（音量/媒体/亮度），按钮 64×44 与 88×44

## 2. 具体不足（按严重度分级）

### 2.1 【P0】卡片与背景对比度不足——边界几乎不可见

实测数值（可复现）：

| 组合 | 对比度 | WCAG 要求 | 判定 |
|---|---|---|---|
| card `#141E32` vs bg 顶部 `#0B1220` | **1.12:1** | ≥3:1 | ✗ 不合格 |
| card `#141E32` vs bg 底部渐变 `#0E1B33` | **1.03:1** | ≥3:1 | ✗ 几乎为零 |
| text `#F3F7FF` vs card | 15.50:1 | ≥4.5:1 | ✓ 合格 |
| sub `#8CA3C7` vs card | 6.48:1 | ≥4.5:1 | ✓ 合格 |
| accent `#22D3EE` vs card | 9.21:1 | ≥4.5:1 | ✓ 合格 |

**关键洞察：文字对比度全部合格，但卡片边界完全不合格。** 这正是照片里"能看到内容却看不清容器"的原因。

更严重的是**校验器漏掉了这一项**：`profile.py:166-169` 只检查 `text` 对 `bg`/`card` 的对比度 ≥4.5，**从不检查 card 与 bg 的对比度**。所以用户换主题时，界面可以合法地变成"一片糊"。

五个内置主题预设（`web_assets/app.js:8-14`）都有同样问题——它们都是"深底+微亮卡片"的同类色相。

### 2.2 【P0】大面积死区——照片中最刺眼的问题

**环境页（照片 1）最严重**：默认配置为 `layout: grid_2x2, widgets: [environment, clock]`，两个组件各占 1 单元，都落在**第一行**：

```
实际占用：y 56 ~ 246（两张 148×190 卡片）
空白区域：y 246 ~ 452 = 206px，占屏幕 43%
```

照片完全印证：卡片只占上半屏，下半屏是纯渐变空场。

**AI 页（照片 3）**：满页卡片 390px 高，但内容只占顶部约 124px，空洞约 270px。照片中"Claude Code / Codex / ZCode"下方是一大片空白。

**电脑页（照片 2）相对最好**，因为 4 个组件恰好填满 2×2。但卡内元素断裂：数值在 y=62，副文本在 y=156，**相距 94px**，导致"64%"与"10.9/16.0 GB"分属两块，视觉上不相关联。

**根因**：`make_generic` 与 `make_ai` 用硬编码 y 偏移，卡片高度固定 190/390px，没有按"实际组件数"或"内容实际高度"分配空间。栅格只定义了 4 插槽（2×2），但 1~2 个组件时不做纵向拉伸。

### 2.3 【P0】触控热区偏小

| 元素 | 实际尺寸 | 问题 |
|---|---|---|
| 底部页码圆点 | **34×24px** | 高度 24px 远低于 44×44 可触下限 |
| 控制中心按钮 | 64×44 / 88×44 | 勉强够高度，但无按压反馈样式 |
| 启动器图标 | 96×90 | ✓ 合格 |

**附带缺陷**：`ui.cpp:358-361` 的间距计算与实际绘制不一致——

```cpp
int total = n * 34 + (n - 1) * 6;   // 用 6px 间距算总宽
int x0 = (SCR_W - total) / 2;
for k: box(..., x0 + k * 40, FOOT_Y, 34, 24);   // 实际用 40px 步进（34+6）
```

总宽按 `6px` 间距算、绘制按 `40px` 步进，当 n=3 时 `total=114`、`x0=103`，但实际第 3 个圆点右缘到 `103+80+34=217`，而非居中的 `320-217=103`。**圆点组实际偏左，且 n 越大偏移越明显。**

### 2.4 【P0】字体层级倒挂

`ui.cpp:230-231`：

```cpp
view.main = label(view.root, "暂无会话", 20, text_color, ...);   // 主状态 20px
view.sub  = label(view.root, "等待 AI 编辑器活动", 32, accent, ...);  // 次状态 32px
```

主状态用 20px、副状态用 32px，且副状态用 accent 亮色。照片 3 中"等待编辑器活动"确实比"暂无活跃会话"更大更绿——**视觉权重与信息重要性完全相反**。

同样的倒挂出现在 `make_generic`：compact 模式下 main 用 16px、非 compact 用 24px，但两者都远大于 16px 的 sub。

**可用字号只有 4 档**（`ui.cpp:62-63`）：`cn_48 / cn_32 / cn_24 / cn_16`。在 320×480 上做 7 类组件，层级粒度不足，想做"标题/主值/次值/说明"四级需要 5~6 档。

### 2.5 【P1】状态反馈缺失

| 场景 | 当前表现 | 问题 |
|---|---|---|
| 传感器读取失败 | `isnan(g_temp)` → 显示"温度不可用" | ✓ 符合可信状态原则 |
| 数据过期 | **无任何标识** | 不显示"最后有效时间"（PRD §5 场景 D 要求） |
| 电脑离线 | 标题右侧"电脑离线"红色小字 | 字号 16px，在 320px 宽屏上过于微弱 |
| GPU 不可用 | "未提供" / "GPU 不可用" | ✓ 合理 |
| 页面切换 | 150ms 淡入淡出 | 无过场指示，多任务时易迷失 |
| 按压反馈 | **无按下态样式** | `button()` 未设置 `LV_STATE_PRESSED` 样式，触摸"没反应" |

### 2.6 【P1】对齐与留白细节

| 问题 | 数值 | 位置 |
|---|---|---|
| 栅格间距不一致 | 水平 8px / 垂直 6px | `make_hardware` 与 `build_page` 用了两套间距 |
| 底部余量仅 4px | 页码圆点底边 476，屏幕 480 | `FOOT_Y=452` + 24px 高，过于贴边 |
| 卡片内边距不统一 | hw_cards 标题 y=10、数值 y=62、副文本 y=156 | 底部留 34px、顶部 10px，严重不对称 |
| 标题与提示行重叠风险 | 标题 y=8（20px→实高约 24），提示行 y=30 | 间隙仅 2px，照片 1/3 中可见拥挤 |

### 2.7 【P1】分辨率适配：无

`SCR_W/SCR_H` 在 `ui.cpp`、`display.cpp`、`display.cpp` 的触摸配置（`x_max=319/y_max=479`）中**三处硬编码**。所有布局坐标为绝对像素常量。

换分辨率需要同时改 3 处 + 重算全部坐标 + 重新验证 8KB 配置预算。**当前架构不具备分辨率适配能力**，这是产品化前的阻塞项。

### 2.8 【P2】其他

- `view.extra[8]` 中 hw_cards 占用 `extra[0..7]`，ai 占用 `extra[0..3]`，余量仅 1——**扩展新组件极易越界**
- `render_all()` 每秒对全部页面重绘（`ui_theme_tick`），虽靠 `set_text` 的 strcmp 短路避免无谓刷新，但 6 页 × 4 组件的字符串比较在 PSRAM 上仍有开销
- `alarm_tick` 中 `stop_alarm(nullptr)` 传空指针（`ui.cpp:573`），当前 `stop_alarm` 未解引用参数所以安全，但属脆弱写法

## 3. 优化方向

### 3.1 布局结构调整

**核心原则：从"固定偏移"改为"按内容分配"。**

**方案 A：栅格按实际组件数自适应高度**（改动小，收益大）

```
当前：所有 grid_2x2 组件固定 190px 高
改为：可用插槽 4 个，实际 n 个组件 → 每卡高 = min(190, BODY_H * 2 / max(2, n))
      n=1 → 单卡 304×390（满页，避免照片 1 的 206px 死区）
      n=2 → 190px（保持现状）
      n=4 → 190px（保持现状）
```

**方案 B：AI 页主状态放大、副状态降级**

```
main：20px → 32px（主状态，最大视觉权重）
sub ：32px → 20px（降级为 accent 色的辅助说明）
extra：16px 保持（工具来源）
```

这样四级层次清晰：主状态 32 > 副状态 20 > 说明 16 > 页脚 16。

**方案 C：卡片内元素垂直居中成组**

```
hw_cards 每卡 148×190：
  标题   y=14  16px
  数值   y=52  32px   ← 与标题间距 38
  副文本 y=100 16px   ← 与数值间距 48，底部留 74px 居中
改为内容整体居中：
  组高 = 16 + 8 + 32 + 6 + 16 = 78px，起点 y = (190-78)/2 = 56
```

**方案 D：页码圆点重算 + 扩大热区**

```
修正间距 bug：total = n*34 + (n-1)*6，步进用 34+6=40
实际改为：圆点 44×44（含透明外扩热区），视觉仍是 34×24
     x0 = (320 - (n*44 - (44-34))) / 2
底边留白：FOOT_Y 从 452 提到 444，保证 ≥12px 底部余量
```

### 3.2 视觉规范

**配色（新增 token，建议写入 `config.h`）**

| 用途 | 现行 | 建议 | 理由 |

| card | `#141E32` | **`#1C2942`** | 与 bg 对比度提到 ≥1.6:1 |
| card 描边 | 无 | **`#2E4370`，1px** | 让边界在低对比屏上仍可辨 |
| text | `#F3F7FF` | 保持 | 15.5:1 合格 |
| sub | `#8CA3C7` | 保持 | 6.48:1 合格 |
| accent | `#22D3EE` | 保持 | 9.21:1 合格 |

**同时必须修校验器**：在 `profile.py` 增加 card↔bg 对比度检查（阈值 1.5:1，低于 3:1 时警告而非拒绝，因为深色主题难达 3:1）。当前五个主题预设同步调整。

**字号阶梯（4 档 → 5 档）**

| 语义 | 现有 | 建议 | 用途 |
|---|---|---|---|
| display | 48 | 48 | 主状态（AI 专注） |

**间距刻度（8px 基准）**

```

卡片内边距统一 12px
栅格间距统一 8px（水平与垂直一致）
```

**触控热区**

| 元素 | 最小热区 | 实现方式 |
|---|---|---|
| 页码圆点 | 44×44 | 视觉 34×24 + 透明扩展 |
| 控制中心按钮 | 64×48 | 现 64×44，加 4px |
| 启动器图标 | 96×90 | 现状合格 |
| 卡片（可点） | 整卡 ≥44 | AI 任务行已 284×56 合格 |

**按压反馈**：为 `button()` 增加 `LV_STATE_PRESSED` 样式（背景提亮 15% + 缩放 0.98），让触摸有即时回应。

### 3.3 交互与状态提示设计

| 改动 | 说明 | 对应 PRD |
|---|---|---|

| 按压反馈 | 所有可点元素加 pressed 态 | §7"按下、提交、等待结果分别反馈" |

## 5. 附：核实方式

所有数值均可复现：

- **对比度**：按 WCAG 2.1 相对亮度公式计算 `(#141E32 vs #0B1220) = 1.12:1`、`(#141E32 vs #0E1B33) = 1.03:1`
