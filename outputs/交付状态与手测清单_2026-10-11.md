## 二、需要你亲手确认（自动化覆盖不到）

1. **闹钟「稍后 5 分」按钮**：设一个 1 分钟后的闹钟，响铃时点「稍后 5 分」
   → 应停止闪烁，5 分钟后重新响铃。（固件触屏交互无法远程模拟）
2. **系统日历授权**：macOS 已拒绝 CLI python 访问日历。到 系统设置 → 隐私与
   安全性 → 日历 手动放行 python，回工作台 设置 → 系统 点「立即刷新」，
   自检面板「系统日历」应变绿并列出条数。
3. **手机推送真机**：设置→系统 填 Bark/ntfy 地址保存，让一个会话进入
   「等你回复」，手机应收到推送；23:00-07:30 安静时段内不推。
4. **Windows**（如有机器）：按 client/PACKAGING-WINDOWS.md 打包 + 验证
   pycaw 音量回显 / SMTC 曲名。

## 五、本次复核：仍需开发的内容

### P0：正式交付前应完成

1. **闹钟状态持久化与离线计时（已完成）**
   - 最近触发实例和稍后截止时间已写入 NVS，软件重启后不会重复触发或丢失稍后闹钟。
   - 主机断连后使用本地 `millis()` 推进完整日期时间，支持跨日，不再受 10 分钟同步窗口限制。
   - 硬件没有电池 RTC：设备完全断电期间无法走时；恢复供电并收到主机时间后，30 分钟内的稍后闹钟可补响。若未来要求彻底脱离电脑，需增加 RTC 模块。

2. **闹钟错过策略与可选稍后时长**
   - 目前只有固定 5 分钟，且只覆盖正常运行中的点击路径。
   - 补充 5/10/30 分钟，定义电脑休眠、设备断连、跨日和时区变化后的行为。
   - 建议默认策略：错过不补响，只进“需要处理”；用户可开启“恢复后补响一次”。

3. **macOS 正式应用包与日历授权**
   - 当前 CLI Python 被日历 TCC 拒绝，需要用户手工放行，普通用户很难理解。
   - 现有 PyInstaller 产物是单文件命令行程序，并非带用途说明、签名和稳定身份的 `.app`。
   - 应提供正式 `.app`、`NSCalendarsUsageDescription`、代码签名/公证、托盘启动和升级策略，让系统权限绑定 WorkBuddy，而不是某个 Python 解释器。

4. **完成第二节三项本机手测并留证**
   - 闹钟稍后、系统日历、手机推送至少各保留一次截图/时间记录/实际结果。
   - Windows 若不作为本次首发平台，应从“待验收”改成明确的“后续平台”，避免阻塞 macOS 交付。
