# 竞品对比分析：宠物/角色系统与布局体系（GlanceMate Bridge 5.31.7 vs 本项目 0.1.0）

分析日期：2026-10-11 晚
输入：竞品 8 张截图（任务视图四种布局、息屏主题、拖拽编辑器、角色库、默认主题库）

---

## 一、关键判断：竞品与本项目同源

竞品 UI 结构与我们**完全同源**：任务视图/息屏显示/其他视图/历史记录/设置五栏、
四种布局预设（状态聚焦/任务时间线/角色陪伴/数据看板）、息屏表盘（时序/方寸仪表）、
「电脑方案预览」左栏——连图 1 里的「任务补充/任务数值/其他任务/空闲时显示」参数组，
**正是我们在重构时删除的 tv.\* 参数集**（当时判定：它们只喂浏览器效果图、从不经 CFG
下发到设备）。

这个判断需要修正：竞品证明这些参数**在设备端可以落地**。我们删掉的不是坏设计，
而是没做完的设计。「先复制完全一样」的最大资产就是：tv.* 的字段设计我们有现成定义，
照竞品截图逐项实现设备端渲染即可。

## 二、竞品宠物/角色系统拆解（逐截图）

### 图 8：角色库
- 6+ 角色：绿色耳麦猫（默认，戴耳机猫）、折耳团子、折耳团子-动态版、海獭小队友、
  云芽（云朵拟人）、薄荷小方（小机器人）——均为高质量 3D 渲染级形象

### 图 3：角色陪伴布局（宠物的主舞台）

## 三、逐项对比：竞品 vs 我们

| 能力 | 竞品 | 我们 | 差距级别 |
|---|---|---|---|
| 角色形象质量 | 3D 渲染级（6+ 角色） | 像素机器人 + 猫/小鸡色块换色 | ★★★ 视觉代差 |
| 角色数量与生态 | 6+、动态版、导入/分享/改名 | 3（机器人/猫/小鸡），不可扩展 | ★★★ |
| 角色表情 | 全状态表情差分 + 预览页 | 9 状态（程序绘制的小变化） | ★★ |
| 场景背景 | 窗边小院等多场景 | 无（纯色/渐变背景） | ★★★ |
| 氛围联动 | 昼夜/天气/动态特效开关 | 无 | ★★ |
| 角色动作 | 打字动作、完成反馈、提醒休息 | 状态表情切换 + 睡觉/问候 | ★★ |
| 互动养成 | 喂食等（图 4 未展开，我们有积分暗示） | 喂食/喝水/运动三状态条 | ≈（我们此处不落后） |
| 布局预设 | 四种，参数可调且**设备端生效** | 四种预设存在，但无可调参数 | ★★ |
| 任务时间线 | 设备端时间线布局 + 范围/时间配置 | 无独立时间线（AI 列表近似） | ★★ |
| 数据看板 | 多智能体积分/费用/Token + 指标勾选 | ai_cost 单卡（今日总量） | ★★★ |
| 拖拽编辑器 | 24 积木画布编辑器 + 组合/拆开 + 导入导出 | 无（页面编排=固定组件槽位） | ★★★ 架构级 |
| 农历节气 | 组件级 + 息屏主题 | 无 | ★★ |
| 布局/主题分享 | 布局导入导出、主题保存/我的主题/旧页库 | 主题库有，布局无导出 | ★ |
| Web↔设备预览分离 | 「此角色尚未应用到小屏」同构 | 同构 | ≈ |

后者我们十轮加固后可能是领先的（竞品截图无证据，保守说不落后）。
表现层差距里，视觉代差（3D 角色）和拖拽编辑器是两座大山。

## 四、「先复制、再超越」的复制路线

原则：**效果复刻，路径不必相同**。竞品的 3D 角色在 ESP32 上不可实时渲染，
但可以做成**预渲染图集资源**（竞品大概率也是图集/视频帧，不是实时 3D）。
我们已有 JPEG 解码（JPEGDEC）、背景图分帧上行、LittleFS 存储三个先例，
角色资源管线是它们的组合。

### M-R1 布局与参数对齐（复刻图 1/3/7 的可调部分）——约 2-3 轮
1. profile 新增 `tv` 参数组（字段照抄我们删掉的 tv.* 设计 + 竞品截图逐项）：
   任务补充（步骤与结果/最近消息/不显示）、任务数值（用时/用量/自动/不显示）、
   其他任务（显示/不显示）、空闲时显示（聚焦/角色陪伴/看板/时间线）、
   时间线展示范围与时间信息、左上角名称（自动/指定）
2. CFG 下发（profile JSON 加字段）+ 固件 AI 页/时间线页按参数渲染
3. **任务时间线布局**：固件新 render（条目=工具·状态·时间/标题，范围可配）
4. **空闲时自动切换**：空闲超时后切到角色陪伴/看板（复用 saver 的空闲检测）
5. Web 任务视图把删掉的 tv.* 控件加回来（这次它们是真的了）
验证：每个参数改动实拍前后对比（screen_regression 扩场景）

### M-R2 角色图集管线（复刻图 8 的单角色效果）——约 3-4 轮
1. 资源包格式：`{meta.json(角色名/状态表/帧表), frames/*.jpg}`，走 IMG= 分帧
   通道扩展（IMG2= 或 IMG 多槽位），存 LittleFS
2. 设备端：状态→帧映射（思考/生成/工具/等输入/出错/完成/睡觉/问候），
   JPEG 解码到 PSRAM 缓存当前角色，状态切换换帧；可选 2-4 帧循环（动态版）
3. 内存预算：角色层 200×240 RGB565 ≈ 96KB/帧 × 当前状态 2 帧 ≈ 192KB PSRAM
   （8MB 足够）；全屏场景背景走背景图通道（76KB JPEG 先例）
4. AI 生成 1 个示范角色图集（6-9 状态 × 1-3 帧）走通全链
5. 保留像素机器人作为「无资源包时的缺省角色」（诚实降级）

### M-R3 角色生态与氛围（复刻图 3/8 完整体验）——约 3 轮
1. 多角色管理：角色列表/切换/改名/删除；导入=资源包上传；分享=资源包下载
2. 场景背景：全屏 JPEG 场景图（窗边小院等，AI 生成）+ 角色层合成
3. 氛围联动：昼夜 tint（按时段叠加半透明色层）、天气 tint（联动天气代码）、
   完成反馈（任务完成时切「开心帧」2 秒）、偶尔提醒休息（久坐切「伸懒腰帧」）
4. 角色显示内容叠加：竞品图 3 的可勾选字段（名称/用时/模型/Token）按 tv 参数渲染

### M-R4 拖拽编辑器（复刻图 5）——约 5-8 轮，唯一架构级变更
1. profile v2：从「widgets 槽位 + tv 参数」演进为**元素树**（组件实例：
   类型/位置/大小/层级/样式/数据绑定；组合=子树）
2. 设备渲染器：布局算法 → 元素树遍历渲染（LVGL 对象按树创建，仍受 320×480 约束）
3. Web 画布编辑器：组件库/拖拽/属性面板/撤销重做/吸附网格/组合拆开/导入导出/
   旧页库/我的主题/应用到小屏
4. 兼容：v1 槽位配置自动迁移为 v2 元素树（老用户无感）
**风险提示**：这是把「配置驱动的四个布局」升级为「自由画布」，设备端内存与
刷新性能要按最坏元素数压测；建议 R4 放最后，前面三级在现有模型内已能复刻
竞品四种布局的**效果**。

### M-R5 数据看板（复刻图 4）——约 2 轮
1. usage scanner 扩展：per-agent 本轮/今日 Token、模型名（已有雏形），
   「积分/费用」无账号体系 → 价格表估算并诚实标注「估算」
2. 设备看板布局：大字指标轮换 + 底部系统行（已有）
3. Web 按智能体分组勾选显示指标（tv 参数组）

### 里程碑对照与排序建议
- R1 → R2 → R3 是宠物/角色主线（用户点名重点），R5 可穿插，
  R4 放最后（或按需裁剪：竞品的 24 积木里我们常用的一半即可达到 90% 观感）
- 每阶段结束跑一次三主题+新布局的实拍回归，角色/场景用实拍像素核对

## 五、超越点（复制完成后的差异化，候选）

竞品截图未覆盖、我们已有的优势应保持并放大：采集健康度（进程识别/新鲜度/
诚实降级）、推送与安静时段、OTA 可靠性、运行自检、损坏自愈——这些是
「可信与可恢复」层，竞品截图里看不到对应深度。
超越候选：闹钟/日程与收件箱联动的小屏提醒、Agent 等待的触屏快捷回应、
多机采集聚合。
