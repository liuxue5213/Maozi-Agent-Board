## 一、项目定位与目标

**WorkBuddy 桌面伴侣屏**：ESP32-S3 + ST7796（320×480 竖屏）+ LVGL 8.3 硬件状态屏，配合 Python 桌面客户端（psutil / pyserial / pywebview），把电脑的实时状态、多工具 AI 会话、音乐、多城市天气、桌面宠物投到一块小屏上，并支持触控反控。

**产品目标（已定型）**："桌面陪伴中枢"。客户端是大脑、设备是显示+触控；结构化 KV 下行而非图片帧；诚实显示（绝不假数据）。

### 7. 宠物可读性（今日最后一轮，烧录实拍 ✅）
- 用户反馈「显示不全」→ 逐像素排查证明**从未被裁切**，根因是对比度：机器人身体 0x1A2A4A≈卡片底色，四肢无描边完全隐形。
- 修复：身体提亮 0x46689C（四肢继承显形）、眼部光晕 30%→50%、嘴宽按 PetParts.sz 缩放（页面体 2 倍曾只有 12px 嘴）。位置左移 5px（234→229）。
- color-map.json robot.body 三元组（hex/rgb565=4353/flushWord=5343）+ 预览 fallback 同步。

### 8. SMC 温度/风扇：从「无解搁置」到「授权即解」（当晚追加）

## 六、关键风险与流程教训

1. **🔴 在途工作树未提交**——最高即时风险，见 P0-1。本文档早间版已提出，**至今未执行**。
2. **🟠 并行 ZCode 会话同改一文件**——已多次互相覆盖（app.js 曾因此瞬态空白下拉）。规则：读文件前先验证落盘状态；改动前后 grep 断言。
3. **🟠 批量 heredoc 补丁**——脚本在第一个失败处中止而前面的 sub 已落盘（踩坑 3 次）。每批后必须 `node --check`/冒烟 + grep 数 token。
4. **🟠 真机联调滞后于单测**——270 绿不等于屏上对。每加一个屏端功能烧一次、实拍一次（本轮已坚持，保持）。
5. **🟡 MediaRemote 私有框架**——macOS 升级可能失效，需保留虚拟键降级。
6. **🟡 smcpriv 特权组件**——同样依赖系统行为（powermetrics 输出格式/权限），采样器失败时写 err 字段、客户端如实隐藏，不显假值；「T2 无解」类结论今后必须先跑闸门再进文档。
7. **🟡 配色校准批次依赖**——24 格矩阵基于本块屏，换屏需重跑 SELFTEST。
8. **快照诊断纪律**——设备快照 160×240 半分辨率（绝对坐标÷2），1px 细边框会被抹掉，**定位小部件要用亮色部件当判据**；日志时间戳是 UTC（本地 +8）。
