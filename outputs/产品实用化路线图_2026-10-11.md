# AI 触摸状态屏：产品实用化路线图

评审日期：2026-10-11  
评审范围：上位机 Web、Agent 状态采集、串口同步、320×480 触控固件

## 一、产品定位

这个产品最有价值的形态不是“缩小版电脑监控器”，而是放在桌面的工作注意力终端。它应稳定回答三个问题：

1. **现在有什么需要我处理？** Agent 等待回复、报错、任务完成、会议临近。
2. **电脑与工作环境是否正常？** 温度、磁盘、网络或设备连接是否异常。
3. **我能否直接处理？** 确认已知、稍后提醒、切页面、控制媒体、执行安全快捷动作。

首页应该优先展示“需要介入的事项”，没有事项时才展示正在执行的任务和电脑摘要。宠物、主题和背景负责陪伴感，不能盖过这三个主任务。

## 二、当前产品成熟度

### 已形成的能力

- Agent 会话：Claude Code、Codex、OpenCode、ZCode、WorkBuddy 可读取阶段；部分编辑器可检测进程。
- 设备配置：页面清单、主题、布局、组件、CFG 事务同步与设备应用回执。
- 桌面信息：CPU、内存、磁盘、网络、天气、部分温度和风扇数据。
- 本地功能：提醒、日程、闹钟、倒计时、媒体控制、快捷应用、宠物、屏保。
- 维护能力：诊断包、设备快照、配置导入导出、固件升级入口。

### 仍停留在“功能存在”的能力

- Agent 有阶段但没有可信完成百分比，也缺少统一的“需要用户介入”收件箱。
- 日程和闹钟能录入、能显示，但外部日历、稍后提醒、确认记录和错过处理还没有完整闭环。
- 音乐能发控制命令，但曲名、播放状态、当前受控应用和失败原因不够完整。
- 快捷应用仍偏向原始命令，普通用户难以安全配置。
- 趋势有数据，但还没有把异常变成可处理事件。
- 个别功能入口可用，但可靠性、恢复能力和能力说明仍不够产品化。

## 三、必须先修的可靠性问题

| 优先级 | 问题 | 用户影响 | 完成标准 |
|---|---|---|---|
| P0 | Web OTA 限制 3 MB，当前固件约 4.3 MB | 固件升级入口实际不可用 | 根据设备分区能力校验大小；展示上传、写入、校验、重启和回滚状态 |
| P0 | 后台启动和测试曾触发浏览器自动打开 | 打断工作、让用户误以为中毒或程序异常 | 后台启动默认静默；只有用户点击“打开控制台”才打开页面；增加单实例锁 |
| P0 | 同一 Agent 可能出现空项目或重复会话 | 首页信息噪声大，无法判断哪个任务重要 | 会话身份稳定；重复会话合并；项目缺失时显示可理解来源而非“未命名” |
| P0 | 数据来源健康状态分散 | 用户不知道数值是实时、缓存、缺权限还是不支持 | 每个来源显示状态、最后更新时间、权限、最近错误和恢复入口 |
| P0 | 配置失败后的恢复不够直观 | 用户可能以为已经同步成功 | 保留上一有效版本；一键重试、查看原因、恢复设备版本 |
| P1 | Web 预览与固件可能发生几何差异 | 电脑上正常、实屏裁切 | 共用布局常量或快照回归；核心页面必须做实屏截图验收 |

## 四、最值得开发的实用功能

### 1. “需要我处理”收件箱

这是最能建立每日使用习惯的功能。

- 汇总 `WAIT_INPUT`、`ASK`、`ERROR`、刚完成任务、临近日程和硬件告警。
- 每条事项只有三个核心动作：**查看、已知、稍后提醒**。
- 支持安静时段、通知等级和重复提醒间隔。
- 可从 Web 跳转到对应应用或项目；小屏触控只做安全、可撤销的动作。
- 首页在有待处理事项时自动切换；处理后回到用户原页面。

验收：事件产生后，Hook 来源 3 秒内出现，轮询来源 6 秒内出现；用户处理后 1 秒内从设备和 Web 同时消失；重连不重复提醒已经确认的事项。

### 2. Agent 状态中心

不要伪造百分比，重点提高“状态是否可信”。

- 每个工具显示：接入方式、运行状态、会话数、最后事件、项目、需要用户介入数。
- 增加来源适配诊断：日志路径、数据库可读性、权限、解析器版本。
- 支持手动隐藏某个工具或项目，避免多个编辑器产生噪声。
- 增加 Aider、Gemini CLI、Cursor Agent CLI 等适配器时，必须区分“会话状态”和“仅进程检测”。
- 对执行超过阈值、长时间无新事件的会话显示“可能卡住”，不要继续写“执行中”。

验收：关闭工具后不残留假活跃；恢复旧会话可识别；同一会话不会重复；解析失败明确降级为仅进程状态。

### 3. 日程与闹钟闭环

当前录入表单只是起点，真正价值在到点后的处理。

- 第一阶段支持本地 ICS 导入和定时刷新，减少手工重复录入。
- macOS 首发可增加系统日历只读接入，权限被拒绝时仍可用手工与 ICS。
- 日程卡显示“距离开始时间”，闹钟支持停止、稍后 5/10/30 分钟。
- 记录已触发、已确认、已错过；设备重启和断线后不重复执行旧闹钟。
- 增加工作日、法定节假日跳过、单次例外和时区变化处理。

验收：创建到上屏不超过 60 秒；到点误差不超过 2 秒；断线重连不重复触发；跨日、休眠唤醒和时区变化均有明确行为。

### 4. 真正可用的媒体控制

- 明确显示当前媒体会话和受控应用。
- 展示曲名、歌手、播放/暂停和可获得的进度。
- 播放、暂停、上一首、下一首、音量动作都返回成功或失败。
- 没有媒体会话时，只打开用户选定的一个播放器，不遍历唤起多个软件。
- 支持“系统当前媒体”与“固定播放器”两种模式。

验收：每次触控只影响一个明确对象；动作 1 秒内有反馈；失败不假装成功；不会弹出多个播放器。

### 5. 硬件健康与告警

- 把 CPU、GPU、风扇、磁盘从“数值展示”升级成健康状态。
- 显示数据来源、采样时间和可信等级；不支持时显示原因。
- 阈值支持默认建议和用户调整，例如磁盘 ≥90%、温度持续高于阈值、风扇异常。
- 告警必须经过持续时间过滤，避免单个尖峰不断闪屏。
- 趋势图标记告警开始、恢复和持续时间，并支持导出。

验收：异常必须持续指定时间才告警；恢复后自动关闭；无传感器权限时不显示 0 或虚假正常。

### 6. 场景模式与轻量自动化

在前五项稳定后再做，这是把已有能力组合成实用体验的方式。

- 预设：工作、会议、专注、夜间、离开。
- 场景可同时设置页面、亮度、自动切页、通知等级和屏保。
- 规则模板：Agent 等待回复、会议前 10 分钟、温度异常、电脑锁屏、指定时间段。
- 只提供白名单条件与动作，不开放无限制脚本自动化。
- 自动动作要有执行记录、冷却时间和手动暂停。

## 五、Web 信息架构建议

保留五个一级入口：

1. **概览**：需要我处理、设备状态、正在运行、电脑健康。
2. **屏幕编辑**：页面、组件、主题、息屏、实屏快照。
3. **日程与控制**：日程、闹钟、媒体、快捷动作。
4. **数据趋势**：硬件趋势、告警事件、数据来源健康。
5. **设置**：设备、Agent 接入、权限、更新、备份与高级标定。

调整建议：

- 宠物从设置一级标签降为“屏幕编辑 → 组件设置”，避免核心设置被兴趣功能分割。
- 历史记录不再单独占一级菜单，操作结果并入概览事件，趋势历史并入数据趋势。
- 首页只展示有数据的摘要；天气、提醒、用量为空时隐藏。
- 全站仅保留一个主要动作“应用到设备”，其他保存尽量自动完成。
- 高级命令、RGB565 和硬件色彩管线放入高级设置。

## 六、建议开发顺序

### 里程碑 A：可信与可恢复

- 修复 OTA 容量和升级回执。
- 后台静默启动、单实例、崩溃恢复。
- Agent 去重、来源健康、数据新鲜度。
- 配置失败重试与恢复上一设备版本。
- 建立首页、宠物页、电脑页、日程页的实屏截图回归。

完成后产品达到“不会打扰、不会撒谎、失败能恢复”。

### 里程碑 B：注意力中心

- “需要我处理”收件箱。
- Agent 等待/确认/错误/完成通知。
- 已知、稍后提醒、安静时段和应用跳转。

完成后产品开始具备每天持续摆在桌面上的理由。

### 里程碑 C：日程闹钟闭环

- ICS 与系统日历只读接入。
- 稍后提醒、错过处理、执行记录。
- 断线、休眠、跨日和时区测试。

### 里程碑 D：控制闭环

- 单一媒体会话、曲名状态和动作回执。
- 安全快捷动作模板。
- 硬件阈值告警与趋势事件。

### 里程碑 E：场景与扩展

- 工作/会议/专注/夜间场景。
- 白名单自动化规则。
- 更多 Agent 适配器和多设备。

## 七、暂缓项目

在里程碑 A–C 完成前暂缓：

- 新增更多主题、背景和宠物形象。
- 复杂宠物养成系统。
- 更多静态系统指标卡。
- 任意脚本插件和开放式动作编排。
- 多设备云同步、账号系统和团队功能。
- 无法提供可靠数据来源的“AI 完成百分比”。

## 八、产品指标

不要以“组件数量”作为成功标准，建议观察：

- 待处理事件识别准确率和误报率。
- 从事件发生到小屏出现的 P50/P95 延迟。
- 配置应用成功率与平均恢复时间。
- 闹钟准时率、重复触发率、确认率。
- 触控动作成功率和明确失败反馈率。
- 每日查看次数、每周实际触控处理次数。
- 因弹窗、错误状态或数据不可信产生的打扰次数。

产品达到可用的标志是：用户不用频繁打开 Web，也能通过桌面小屏发现需要处理的事情，并在一次触控或一次跳转内完成处理。
