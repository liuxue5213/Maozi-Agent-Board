# 屏幕样式重开发指南（2026-10-09）

> 适用：maozi-diy 设备屏配色重做。"色彩太烂"由**两层问题叠加**，必须分层处理。
> ⚠️ 硬约束：本环境无 PlatformIO，固件改动（含 config.h）需本地 `pio run` 才生效；设备端显示受 G/B 通道影响（见 §2）。

---

## 一、屏幕样式由哪三层决定（改哪里）

| 层 | 文件 / 位置 | 角色 | 改了是否立即生效 |
|---|---|---|---|
| **真源** | `~/.workbuddy/profile.json` 的 `theme` 块（运行时经 CFG 下发） | 设备实际用的配色 | 客户端在线即下发；**Web 设置页刷新即时预览** |
| **兜底** | `firmware/src/config.h` 的 `COL_*` | 出厂/未配置时的默认色 | 需 `pio run` 重编译烧录 |
| **应用** | `firmware/src/ui.cpp` 的 `box()/label()/bar_*()` | 颜色如何落到卡片/文字/进度条 | 需重编译烧录 |

**结论**：日常调色只动 `profile.json` 即可，无需编译。要换"出厂默认"才动 `config.h`。

---

## 二、"色彩烂"的两层根因

1. **硬件 G/B 通道错位（🔴 必须先修）**：实机卡片呈草绿（`#3F6A07`），而「紫夜」卡片本应是紫（`#3A2D5C`）。唯一吻合的变换是 **G/B 互换**（`#3A2D5C`→`#3A5C2D`）。
   - ⚠️ LovyanGFX `rgb_order` 只控 MADCTL BGR＝**R/B 互换**，**表达不了 G/B 互换**。盲改 `rgb_order=true` 只会叠加错位。
   - 定论法：烧录 `PANEL_COLOR_SELFTEST=1`（已内置四色校验屏），拍一张照片对照 `config.h` 判读表设 `PANEL_COLOR_ORDER_BGR`；若红显绿/绿显红则非 rgb_order 能解，需查 `LV_COLOR_16_SWAP` + MADCTL 组合。
   - **未修 G/B 前，设备上的任何配色都会偏绿**；但 Web 设置页预览不受影响（普通屏幕），可用它迭代设计。

2. **调色板本身不够好看（🟢 现在就能改）**：原「紫夜」紫得发闷、卡片边界弱。已为你重做两套现代深色配色（见 §三）。

## 四、重开发工作流（推荐循环）

```
1) 设计配色  → 在 profile.json 的 theme 块改 6 个色值（或导入上面 JSON）
2) Web 预览  → 打开 127.0.0.1 设置页，看"设备预览"区（applyDeviceTheme 实时下发，
               颜色正确，不受 G/B 影响）
3) 校验对比度 → 跑 cd client/workbuddy && python3 -c "import profile,json;
               profile.validate_profile(json.load(open('你的profile.json')))"
               （不抛错即达标；规则见 profile.py 202-221 行）
4) 推到设备  → 客户端在线时自动 CFG 下发（前提：先修 G/B，否则设备显绿）
5) 出厂默认  → 若满意，把最终色值写回 config.h 的 COL_* 并 pio run
```

## 五、自己怎么改（三种入口）

- **最省事**：Web 设置页 → 主题库 / 自定义主题，直接调色，刷新预览。
- **导入文件**：Web 设置页"导入配置"选 `outputs/theme-*.json`（P1-3 端点已建）。
- **改源码**：编辑 `profile.json` 的 `theme` 或 `config.h` 的 `COL_*`（后者需编译）。

## 六、注意

- **浅色主题**受 `card↔bg ≥ 1.5:1` 规则限制（白卡 near-white 底天然不达标）。若要浅色，需把 bg 压暗（如 `#D9CFB8` 暖奶油）或放宽该校验规则——属产品决策。
- 设备端最终效果**必须等 G/B 通道修好**才可信；在此之前一切以 Web 预览为准。
- 改 `ui.cpp` 的 `box()/bar_*()` 才能动"布局层级/描边/进度条样式"，那属于视觉结构重做，不止配色。
