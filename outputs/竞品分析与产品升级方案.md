# 竞品分析与产品升级方案：桌面状态屏/AI 陪伴小屏

> 分析对象：GlanceMate Bridge · 桌面状态中心（v5.31.7）  
> 分析目标：为 maozi-diy 项目提供功能补齐、体验优化与差异化竞争的产品方案。



---

## 一、竞品核心画像

### 1.1 产品定位

**GlanceMate Bridge** 将自己定位为「桌面状态中心」——一台放在桌面、通过 USB/无线连接电脑的副屏。它的价值主张不是简单的"第二块显示器"，而是：

- **任务可见性**：把 AI 长任务、当前工作项、时间线余光化，减少切窗。
- **情感陪伴**：用 3D 角色（绿色耳麦猫、折耳团子等）把冷冰冰的状态屏变成"桌宠"。
- **个性表达**：提供主题、表盘、场景氛围，让桌面设备像手机壳一样可换肤。
- **成本意识**：针对 AI 高频用户，聚合 Token/积分/费用，让"烧钱"可感知。

目标用户画像可归纳为：**重度使用 AI 工具、愿意为桌面氛围与效率付费、对设备颜值敏感的个人开发者/创作者/知识工作者**。

### 1.2 信息架构

```
GlanceMate Bridge
├── 概览
├── 任务视图（核心）
│   ├── 默认主题 / 自定义主题
│   ├── 状态聚焦 / 任务时间线 / 角色陪伴 / 数据看板
│   ├── 布局配置（导入/导出/恢复默认）
│   └── 任务显示短名、监测来源
├── 息屏显示
│   ├── 显示方式 / 选择息屏主题 / 编辑息屏画面
│   └── 原有表盘（渲夜 / 翻时 / 时序 / 方寸仪表）
├── 其他视图
├── 历史记录
└── 设置
```

主入口是「任务视图」，内部按"视图模式"组织；「息屏显示」独立成章，说明产品把"不用电脑时的桌面装饰属性"看得很重。

### 1.3 核心功能模块（按截图拆解）

| 模块         | 截图依据 | 关键能力                                                                        |
| ---------- | ---- | --------------------------------------------------------------------------- |

| **主题市场**   | 图 2  | 精选主题 + 我的主题；4 种模板（胡桃液晶、像素花园、便签拼贴、窗边陪伴）；一键应用到任务/小屏                           |

### 1.4 视觉与交互风格

- **整体调性**：奶油白 + 鼠尾草绿 + 深绿点缀，走"清新、治愈、桌面绿植"风格；圆角大、卡片化、阴影轻。
- **字体层级**：标题用粗黑体，正文用常规黑体，辅助信息用灰色；无夸张的科技感，更偏家居/生活化。
- **图标语言**：线性图标 + 少量填充色块；左侧导航用图标+文字，符合桌面端设置页直觉。
- **反馈设计**：选中态用浅绿填充+深色文字；开关、单选组统一为绿色；按钮分主次（主按钮深绿、次按钮白底描边）。
- **布局策略**：三栏为主（预览 / 编辑区 / 设置面板），适配宽屏电脑设置页；小屏预览始终放在左侧，保证"所见即所得"。

## 二、竞品 vs maozi-diy 能力对标

### 2.1 功能矩阵

| 能力域         | 竞品（GlanceMate）           | maozi-diy 当前状态                            | 差距评级              |
| ----------- | ------------------------ | ----------------------------------------- | ----------------- |
| **连接方式**    | USB/无线（未确认，UI 显示"小屏未连接"） | USB 串口（CP210x/CH340）                      | 持平                |
| **硬件形态**    | 专用成品小屏                   | ESP32-S3 + ST7796 320×480 + FT6236 触控，DIY | 竞品更精致，maozi 更开放   |
| **AI 状态展示** | 状态聚焦、任务时间线、数据看板          | AI 列表页（W_AI_LIST）                         | 竞品维度更丰富           |
| **硬件监控**    | CPU/内存/存储 + 网速           | CPU/内存/GPU/磁盘                             | maozi 多 GPU，竞品多网速 |
| **角色陪伴**    | 6+ 3D 角色、表情、场景、动作        | 无                                         | **显著差距**          |
| **主题系统**    | 可视化编辑器 + 模板市场 + 我的主题     | 5 套 JSON 预设 + 自定义 HEX                     | **显著差距**          |
| **息屏显示**    | 4 种表盘、节气、诗词、锁屏隐藏任务       | 无                                         | **显著差距**          |
| **AI 成本看板** | 积分/Token/费用/模型/用量        | 无                                         | **显著差距**          |
| **布局编辑**    | 24 积木拖拽 + 吸附/网格/缩放       | JSON 配置 + list/grid_2x2                   | **显著差距**          |
| **时间/日历**   | 时间、日期、农历与节气              | 时钟、提醒、日历、闹钟                               | 竞品多了农历节气          |
| **配置同步安全**  | 未知                       | A/B 双槽 + CRC32 + schema 校验                | **maozi 领先**      |
| **离线/隐私**   | 依赖客户端在线                  | 127.0.0.1 本地 Web + 串口                     | **maozi 领先**      |
| **成本/开源**   | 商用闭源                     | 开源 DIY，硬件自选                               | **maozi 领先**      |

### 2.2 竞品的三个设计意图

1. **从"状态屏"走向"情感化桌面伴侣"**：角色、场景、表情让玩家对设备产生依恋，提高打开率与留存。
2. **从"展示数据"走向"理解成本"**：AI 用户最敏感的除了时间还有钱，数据看板把 Token、费用、模型直接量化。
3. **从"配置工具"走向"创作工具"**：24 积木可视化编辑器把用户变成主题创作者，产生 UGC 与分享动机。

### 2.3 maozi-diy 的机会点

- **硬件可定制**：ESP32-S3 方案可以接 PIR、DHT11、实体按键、蜂鸣器，做"感知用户在场"的主动交互，这是纯软件竞品做不到的。
- **离线优先 + 无订阅**：竞品如果走订阅或高级角色付费，maozi 可以主打"一次硬件成本、永久使用"。
- **开发者友好**：JSON + Python 客户端，更容易被极客改造、接入 Home Assistant、Obsidian 等生态。
- **显示效果可迭代**：竞品用彩色液晶屏+3D 角色，maozi 的 320×480 屏一样可以走"像素/液晶拟态"风格，用有限分辨率做出高辨识度。

## 三、产品优化与缺失能力补充方案

### 3.1 总体策略

**不直接复制 GlanceMate 的"重角色、重编辑、重表盘"路线**，而是：

> **以现有硬件遥测与 A/B 安全同步为基座，补齐"任务可视化、情感化、个性化"三条体验线，同时把物理传感器变成竞品无法复制的壁垒。**

产品口号建议：

> **"看得见状态的桌面小助理，懂你在场的 AI 陪伴屏。"**

### 3.2 关键功能模块

#### 模块 A：任务可视化中心（补齐 AI 工作流）

**问题**：当前 AI 页只能显示"暂无活跃会话"，无法展示多任务、时间线、成本。

**方案**：

| 子功能         | 说明                                          | 优先级 |
| ----------- | ------------------------------------------- | --- |
| **状态聚焦模式**  | 单任务大字号展示：当前任务名 + 主状态 + 本轮用时 + 最近消息          | P0  |
| **任务时间线模式** | 展示"进行中 / 已完成"事件流，支持"仅进行中"与"含近期完成"两种范围       | P0  |
| **多任务卡片**   | AI 列表页从单槽扩展为 3 行可点击任务（已在 ui.cpp 预留）         | P0  |
| **AI 成本面板** | 展示剩余积分、本轮 Token、本轮费用、当前模型、今日累计              | P1  |
| **数据来源扩展**  | 除 WorkBuddy/ZCode/Codex 外，支持读取本地日志文件/API 轮询 | P1  |

**用户故事**：

- 作为高频使用 AI 助手的开发者，我希望余光就能看到当前 AI 任务的进度与耗时，以便减少切窗打断心流。
- 作为多模型切换的用户，我希望小屏显示本轮 Token 与费用，以便控制 API 成本。

#### 模块 B：轻量化角色陪伴系统（补齐情感化）

**问题**：无角色系统，设备只是工具，缺少陪伴感与打开动机。

**方案**：

| 子功能          | 说明                                                    | 优先级 |
| ------------ | ----------------------------------------------------- | --- |
| **像素/2D 角色** | 由于 320×480 屏不适合 3D 渲染，用 64×64 或 80×80 像素角色精灵图，按状态切换表情 | P1  |
| **状态-表情联动**  | 待机=打盹、任务中=专注、完成=开心、报错=惊讶、高温=擦汗                        | P1  |
| **角色配置页**    | Web 设置页增加"角色"标签：选择/导入/改名；连接小屏后同步                      | P1  |
| **动作气泡**     | 角色偶尔弹出"休息一下吧""任务完成了"等短句（可关闭）                          | P2  |

**差异化**：不走竞品"高精度 3D 角色 + 场景"的重资产路线，而走"像素精灵 + 状态联动"的轻量极客风，降低美术与固件负载。

#### 模块 C：主题与息屏系统（补齐个性化）

**问题**：主题靠 JSON 手动改、无预览、无息屏、无表盘。

**方案**：

| 子功能        | 说明                                                 | 优先级 |
| ---------- | -------------------------------------------------- | --- |
| **主题模板市场** | Web 页内置 8 套模板（科技蓝、胡桃液晶、像素花园、电子墨水、赛博霓虹、暖沙、森林、极简白）   | P1  |
| **实时预览**   | 设置页右侧增加 320×480 仿真画布，改色/改组件即时刷新                    | P1  |
| **息屏表盘**   | 新增 `W_IDLE_CLOCK` 组件：时间、日期、农历、自定义短句；锁屏或长时间无交互时自动切换 | P2  |
| **农历与节气**  | 客户端用 Python `lunardate` 计算农历与 24 节气，下发给固件          | P2  |

#### 模块 D：物理在场感知系统（建立壁垒）

**问题**：竞品是纯软件+屏幕，maozi 有 PIR 引脚预留但尚未启用。

**方案**：

| 子功能            | 说明                             | 优先级    |
| -------------- | ------------------------------ | ------ |
| **PIR 人体感应**   | 用户离开座位 5 分钟后自动息屏/降亮度；返回后唤醒     | P1     |
| **DHT11 环境联动** | 温度/湿度超阈值时角色表情切换或显示提醒           | P1（已有） |
| **实体按键快捷操作**   | 短按切换页面、长按切换主题/息屏、双击暂停/恢复 AI 任务 | P2     |
| **久坐提醒**       | 基于 PIR 在场时长 + 时间，触发"起来活动"提示    | P2     |

**差异化价值**：把设备从"被动显示器"变成"主动感知用户在场的桌面助手"，这是纯软件方案无法低成本复制的。

#### 模块 E：配置与创作工具升级

**问题**：当前配置靠 JSON + Web 表单，编辑效率低、门槛高。

**方案**：

| 子功能          | 说明                                  | 优先级 |
| ------------ | ----------------------------------- | --- |
| **所见即所得编辑器** | Web 页 320×480 仿真画布，支持拖拽 7 类现有组件改变布局 | P1  |
| **布局模板一键切换** | 提供"专注模式"/"数据控"/"陪伴模式"/"极简时钟"四种模板    | P1  |
| **配置导入/导出**  | 已支持 base64；增加 JSON 明文导出与二维码分享       | P2  |
| **撤销/重做**    | 编辑器支持 10 步历史                        | P2  |

## 四、用户流程改进点

### 4.1 当前 maozi-diy 的主要用户流程

```
用户打开 WorkBuddy.command
        ↓
客户端读取 profile.json → 串口下发到 ESP32
        ↓
固件渲染页面
        ↓
用户在小屏上滑/下拉切换页面或启动应用
```

### 4.2 优化后的关键流程

#### 流程 1：首次配置（降低门槛）

```
打开 WorkBuddy.command
        ↓
弹出"选择一个开始模板"（专注/数据控/陪伴/极简）
        ↓
右侧实时预览 320×480 仿真效果
        ↓
一键应用到小屏
        ↓
30 秒内看到设备变化
```

**改进点**：把"空白 JSON 配置"变成"模板 + 预览 + 一键应用"，降低首次使用门槛。

#### 流程 2：日常查看 AI 任务

```
AI 开始工作 → 客户端推送任务状态到固件
        ↓
小屏切换到"任务时间线"视图
        ↓
显示任务名 + 状态 + 本轮用时 + 角色表情（专注态）
        ↓
任务完成 → 角色表情切换为开心 + 弹出"完成"提示
        ↓
用户点击任务行 → 客户端窗口自动切到对应 AI 会话
```

**改进点**：把"状态展示"变成"状态+情感+操作入口"的闭环。

#### 流程 3：息屏/在场感知

```
用户离开座位 → PIR 检测无人 → 5 分钟后息屏表盘
        ↓
用户返回 → PIR 触发 → 恢复到之前的工作视图
        ↓
久坐 50 分钟 → 角色弹出"休息一下吧"气泡
        ↓
用户短按实体键 → 暂停/恢复提醒
```

**改进点**：让小屏像智能灯一样感知用户存在，减少无效显示耗电，增加关怀感。

#### 流程 4：主题分享

```
用户在 Web 编辑器调好主题
        ↓
点击"保存到我的主题" → 可命名、可导出 JSON
        ↓
点击"分享到社区" → 生成 GitHub Issue / 飞书文档链接（可集成）
        ↓
其他用户点击"导入主题" → 粘贴 JSON 或二维码图片
```

**改进点**：建立 UGC 闭环，把 maozi 从个人工具变成有社区的内容生态。

## 五、差异化价值总结

| 维度        | 竞品（GlanceMate）      | 优化后的 maozi-diy                        |
| --------- | ------------------- | ------------------------------------- |
| **核心体验**  | 3D 角色 + 主题市场 + 数据看板 | 状态可视化 + 像素角色 + 物理感知                   |
| **成本模型**  | 硬件+可能的订阅/付费角色       | 开源 + 一次性硬件成本                          |
| **隐私**    | 依赖客户端在线同步           | 127.0.0.1 本地 + 可选 MQTT/Home Assistant |
| **可定制性**  | 软件层面受限              | 硬件可换、固件开源、协议公开                        |
| **情感连接**  | 高精度 3D 角色           | 像素精灵 + 在场感知 + 主动关怀                    |
| **开发者生态** | 弱                   | Python 客户端 + JSON 协议，易接入第三方工具         |

**一句话差异化**：

> **GlanceMate 是"卖给你一块精致的状态屏"，maozi-diy 应该成为"你能自己造、能感知你、能接入你整个工作流的桌面 AI 助理"。**

## 六、实施路线图

### Phase 1：基础体验修复（P0，1-2 周）

1. **UI 可辨识性修复**（已部分完成）
   - card 对比度 ≥1.5:1、文字对比度 ≥4.5:1、卡片描边
   - 20px 中文字库、AI 页字号层级修正
   - 页码圆点热区 ≥44×44、按压反馈
2. **任务可视化**
   - 在现有 `W_AI_LIST` 基础上增加状态聚焦与任务时间线两种子视图
   - 支持展示"当前任务名 + 主状态 + 本轮用时"
3. **配置超时兜底**
   - 串口同步增加超时与 NAK 原因统计
4. **首次配置引导**
   - Web 页增加"选择模板"入口与实时预览画布

### Phase 2：情感化与个性化（P1，3-5 周）

1. **像素角色系统**
   - 设计 3-5 个 64×64 像素角色，每个角色 6-8 个表情
   - 增加 `W_COMPANION` 组件，表情与 AI 状态/硬件温度联动
2. **主题模板市场**
   - Web 页内置 8 套模板
   - 用户可保存"我的主题"
3. **PIR 在场感知**
   - 启用 `PIN_PIR 7`，实现息屏唤醒、久坐提醒
4. **所见即所得编辑器**
   - 仿真画布支持拖拽 7 类组件、切换 list/grid 布局
5. **AI 成本面板**
   - 客户端聚合 Token/费用/模型，新增 `W_AI_COST` 组件

### Phase 3：生态与壁垒（P2，6-10 周）

1. **息屏表盘**
   - `W_IDLE_CLOCK` + 农历节气 + 自定义诗词/短句
2. **配置导入/导出与分享**
   - JSON 明文导出、二维码分享、GitHub 主题仓库集成
3. **实体按键与快捷键**
   - 短按切页、长按切主题、双击暂停提醒
4. **第三方数据源接入**
   - 支持读取 Cursor/Trae/Claude Code 等工具状态日志
   - 可选 MQTT 桥接到 Home Assistant
5. **数据看板**
   - 周/月 AI 使用报告、费用趋势、模型使用分布

## 七、关键指标与北极星

### 北极星指标

**周有效看屏天数** = PIR 触发 ≥N 次且当时屏幕存在非 IDLE AI 状态的天数

- 同时惩罚"装了不用"和"展示了没人看"。

### 驱动指标

| 指标       | 定义               | 目标      |
| -------- | ---------------- | ------- |
| 配置同步成功率  | ACK 成功次数 / 下发总次数 | ≥95%    |
| 首次配置完成率  | 选择模板后 30 秒内成功应用  | ≥80%    |
| 角色互动率    | 用户主动切换角色/表情的比例   | ≥30%    |
| 任务可见使用时长 | 小屏显示 AI 任务的日均小时数 | ≥2h     |
| 息屏唤醒次数   | PIR 触发唤醒的日均次数    | ≥3 次    |
| 主题 UGC 数 | 社区每月新增主题数        | ≥10（长期） |

### 健康指标

- 固件崩溃率 / 串口断连率
- Web 设置页加载时长
- 配置校验失败原因分布

## 八、风险与 Non-goals

### 8.1 主要风险

| 风险                               | 影响 | 应对                                         |
| -------------------------------- | -- | ------------------------------------------ |
| ESP32-S3 内存/Flash 不足以跑角色精灵与复杂 UI | 高  | 使用像素图而非 3D；Flash 不足时考虑 PSRAM 或外接 SPI Flash |
| 320×480 屏放不下竞品级视觉                | 中  | 走"高密度信息 + 像素风"路线，不追求照片级角色                  |
| 第三方 AI 工具接口不稳定                   | 中  | 抽象数据源接口，支持文件轮询/HTTP/API 多种方式               |
| 用户创作内容版权                         | 低  | 官方提供 CC0 素材，用户上传自担责任                       |

### 8.2 Non-goals（本阶段明确不做）

1. **不做 3D 角色渲染**：超出 ESP32-S3 能力与项目美术预算。
2. **不做自己的 AI 模型**：只展示外部 AI 工具状态，不替代它们。
3. **不做订阅制付费内容**：保持开源与一次性硬件成本，与竞品商业模式错开。
4. **不做手机 App**：先深耕桌面端 Web 配置与固件体验。
5. **不做视频/流媒体显示**：320×480 屏主攻信息与陪伴，不替代显示器。

## 九、下一步建议

1. **先固化 Phase 1**：把已有的 UI 修复和任务可视化落地，尽快烧录验证 20px 字库与配色效果。
2. **做 3-5 个种子用户访谈**：确认"任务可视化"与"角色陪伴"哪个才是真实痛点，避免凭竞品反推需求。
3. **角色美术走 sample-first**：先画 1 个像素角色的 6 个表情，在屏上验证后再批量。
4. **PIR 传感器优先采购**：这是建立"在场感知"壁垒的最小硬件投入。
