## 2. 🔴 P0 缺陷：G/B 通道错位（卡片变绿）

这是本次分析最重要的发现，属于**硬件/驱动层缺陷，不是审美问题**。

### 2.1 现象与证据
取样 5 张照片的卡片内部区域（避开文字与描边），量化主色：

| 页面 | 卡片内部实测主色 | G 通道占优像素占比 |
|------|----------------|------------------|
| 电脑（2×2 四卡） | `#3F6A07` `#639028` `#8EBB53` `#A0C96F` | **100.0%** |
| 控制中心 | `#84C875` `#97DA6F` `#548D55` | **71.4%** |
| 环境 | `#79B761` `#6AA050` `#3C7826` | 高 |
| 帽子工作台 | `#7CB758` `#5E963D` `#A3C981` | 高 |

照片中卡片呈**饱和草绿色**，与「紫夜」的紫色 `#3A2D5C` 完全相反。

### 2.2 根因锁定：G/B 对调
「紫夜」卡片色 R=`3A` G=`2D` B=`5C`。若 **G 与B 通道互换**：

```
定义色        #3A2D5C  (紫)
G/B 对调后    #3A5C2D  (绿)   ← 色相与照片实测 #3F6A07 / #8EBB53 完全吻合
```
紫色被渲染成绿色，而**背景恰好是深色系**（`#120B22`，G/B 对调后仍为暗色），所以背景看起来"正常"——这掩盖了故障，只在卡片上暴露。

### 2.3 已排除的其他假设
| 假设 | 结论 |
|------|------|
| 相机白平衡偏色 | ❌ 只能整体偏暖/偏冷，无法把紫变绿 |
| RGB565 字节序颠倒 | ❌ `#3A2D5C`→`#838141`（橄榄），非绿 |
| RGB565 位反转 | ❌ 结果 `#310820`（暗紫红） |
| R/B 互换 | ❌ 结果 `#624020`（棕） |
| **G/B 互换** | ✅ **唯一吻合** |

### 2.4 可能的代码位置（待你本地确认）
`firmware/src/display.cpp` 中 ST7796 的初始化与颜色写入处，重点核查：
- 初始化命令序列里的 **MADCTL / COLMOD** 位设置（是否置了 `BGR` 位而面板实际需要 `RGB`）；
- `LV_COLOR_16_SWAP` 与 `LV_COLOR_DEPTH 16` 的组合是否与面板匹配；
- 若存在 `swap_bytes` / 手写 RGB565 打包代码，确认高/低字节与 R/B 位序。

**建议验证**：把某张卡片临时改成纯红 `#FF0000` 与纯蓝 `#0000FF` 各刷一屏。若屏上红蓝互换 → 确认 R/B 或 BGR 位错；若红显示为绿 → 确认 G/B 错位。这是 2 分钟能定论的实验。

### 2.5 影响面
- 该错位影响**所有经主题下发的颜色**：`accent` 紫→绿、`sub` 淡紫→淡绿、`card` 紫→绿。
- 状态色语义被破坏：`COL_OK` 绿与故障色在绿卡片上难分辨（电脑页 `--` 占位符与卡片同色系，already 很难读，见§4）。
- "紫夜"主题完全失效；其余 4 套主题同样会偏色。

## 3. 视觉质感评估（基于当前照片）

### 3.1 做得好的地方
| 维度 | 评价 |
|------|------|
| 信息层级 | 卡片式分区清晰，标题/数值/说明三级明确 |
| 控件尺寸 | `-` `+` 与媒体按钮触控面积充足，44×44 热区符合移动端规范 |
| 一致性 | 5 个页面均沿用"顶栏标题+时间 → 卡片区 → 底部页码点"骨架 |
| 状态表达 | 已静音、播放中都有明确文字状态，不依赖颜色单独表意 |
| 页码指示 | 底部圆点 + ☰/⚙ 固定按钮，触达可靠 |

### 3.2 明显不足
| 问题 | 证据 | 严重度 |
|------|------|----------|
| 卡片绿到"发光" | 照片中卡片呈荧光绿，视觉刺眼、廉价感强 | 🔴 高（根因即 §2） |
| 文字对比不足 | 卡片内标题（绿上深蓝紫）与 `--` 占位符几乎不可读 | 🔴 高 |
| 页面大片空白 | 图2「应用启动器」整屏只有标题+居中提示，主体 70% 空白 | 🟡 中 |
| 时间折行 | 图3「本地时间」`16:12:27` 被折成两行，`2026-10-` 后被截断 | 🟡 中 |
| 数值字号失衡 | 图4 卡片标题与其下`--` 字号接近，缺主次 | 🟡 中 |
| 文字边缘重影 | 所有照片可见明显描边/重影（拍照摩尔纹+可能的 SPI 边缘） | 🟡 中 |

### 3.3 关于"文字重影"的辨析
照片里的重影有两个叠加来源，需区分：
1. **摩尔纹**：手机翻拍 LCD 必然产生彩色干涉条纹——图 1/4 卡片上的波纹状纹理即此，属**拍摄伪影**，不代表屏幕有问题。
2. **可能的真实重影**：SPI 40MHz 降频后仍若在实机看到笔画拖影，才是硬件问题。

→ 结论：**不要把翻拍摩尔纹当成固件缺陷**。请用实机直视或截屏（`Web 设置页`有实时预览）复核。

## 附：取色方法（可复现）

```python
# 屏幕区域取样（避开黑边框、水印、排线）
img.crop((int(w*0.10), int(h*0.10), int(w*0.88), int(h*0.93)))
# 量化主色
box.quantize(colors=5, method=Image.MEDIANCUT)
# 判定绿偏：G 通道占优像素占比
gr = sum(1 for r,g,b in px if g>r+8 and g>b+8) / len(px) * 100
```
