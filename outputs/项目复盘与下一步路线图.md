### 4.4 每项的具体内容与预期

**P0-1 编译验证与烧录 QA**
- 预期目标：固件 `pio run` 零错误；OTA 升级在真机跑通一次；本会话的 cn_20/SPI/对比度/栅格改动在实机确认无回归。
- 影响范围：全固件；回归重点是 `lv_obj_align` 用法、cn_20 链接、SPI 40MHz 实机无重影、`build_page` 自适应在 7 类组件 × 2 布局共 14 种组合下不溢出/不重叠。
- 风险：可能暴露隐藏编译错误（如 `bot_*` 对象树、`bgimg` 背景图 API 误用）；OTA 首刷若失败需串口救砖。

**P0-2 flash 容量治理**
- 预期目标：`pio run` 后 app 分区占用 < 槽位 90%；确认 OTA 双槽均能容纳。
- 动作：① 移除 cn_16（`platformio.ini` 去 `-DCN_16=1`、`fonts.h` 去 `extern`、评估是否删 `.c`）；② 评估 `lv_font_conv` 去掉 `--no-compress`（可缩 ~30–50%）；③ 若仍紧，将字库载入 PSRAM（`BOARD_HAS_PSRAM` 已开）。
- 影响范围：字体构建链（`gen_fonts.py`）+ 链接；不改运行时逻辑。
- 风险：移除 cn_16 后若有隐藏引用会链接失败（已确认 `ui.cpp` 无引用，但仍需编译确认）；压缩字体需验证 LV_COLOR_DEPTH 16 下渲染正常。

**P1-1 PIR 在场感知**
- 用户故事：`作为设备，我希望在人靠近时自动唤醒、离开后延时息屏，以便不打扰又能主动呈现信息`。
- 预期目标：PIR 触发 → 唤醒并标记"有效看屏"；无人 → 进入息屏主题（已有）。看屏次数按分钟去重后回传客户端。
- 影响范围：`main.cpp` 循环 + `proto.cpp` 新增上行字段 + `telemetry.py` 落库。
- 风险：PIR 误触发（宠物/光线）→ 需去抖与阈值；与触摸唤醒逻辑并存需防冲突。

**P1-2 行为遥测**
- 预期目标：客户端记录每日 PIR 唤醒次数、各页面停留占比、同步成功率、SLOW/FW 告警次数；生成周度健康报告。
- 影响范围：`telemetry.py`/`app.py` + 新增本地 SQLite（或 JSON 滚动日志）；**不**新增任何外部上报（隐私合规）。
- 风险：日志膨胀 → 需滚动清理；与首份报告"反馈收集策略"一致，坚持本地化。

**P1-3 配置分享**
- 预期目标：Web 设置页可"导出当前配置为 JSON / 导入 JSON / 一键套用主题预设"。
- 影响范围：`web.py` 新增两个 HTTP 端点 + `app.js` 按钮；复用现有 `validate_profile`（已有严格校验）。
- 风险：导入非法配置需在客户端校验拦下（已有校验器，风险低）。

### 4.5 北极星与护栏指标
- **北极星（P2 启用）**：`周有效看屏天数` = 当周 PIR 触发 ≥N 次且当时屏幕存在非 IDLE AI 状态的天数（同时惩罚"装了不用"和"展示了没人看"）。
- **护栏（现在就该看）**：同步成功率、NAK 原因分布、同步中位耗时、在线时长占比、固件版本分布、SLOW/FW 告警频次。
