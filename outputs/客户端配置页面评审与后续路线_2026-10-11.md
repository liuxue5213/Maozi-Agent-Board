# 客户端配置页面评审与后续路线

评审日期：2026-10-11  
评审对象：`http://127.0.0.1:8765`

## 一、总体判断

当前 Web 客户端已经具备完整产品雏形，视觉语言统一，浅色背景、白色卡片和紫色主色适合配置工具。真正影响使用体验的问题主要集中在三点：

1. 同一件事分散在多个入口，例如“任务视图”和“设置 → 页面编排”都在管理页面与组件。
2. 保存、同步、应用三个概念在不同页面使用方式不同，用户无法快速判断修改是否已经到达设备。
3. 一些控件虽然存在，但没有解释禁用原因、数据来源或应用状态，容易被认为没有作用。

下一轮应先收敛信息架构与同步闭环，再增加新组件和主题数量。

## 二、现场发现的问题

### P0：直接影响正确使用

- 侧栏显示“小屏未连接 / 版本 —”，概览设备卡却显示设备已连接，连接状态不一致。
- 息屏主题的选中边框与右侧预览内容不一致，没有区分“当前已应用”和“刚选择但未应用”。
- 页面编排中的组件库全部显示为禁用，却没有解释是容量已满、组件重复、布局不兼容还是设备离线。
- 不同页面分别使用“保存”“同步”“应用到设备”，有的修改还会自动同步，行为不统一。
- 系统页将接近 100℃ 的 CPU 温度仍显示为普通“运行中”，缺少异常阈值、数据可信度和传感器健康提示。

### P1：明显增加认知负担

- “任务视图”同时包含页面布局、主题、实时预览；“设置”里又有页面编排和主题，入口重复。
- “其他视图”名称过于宽泛，混合提醒、日历、闹钟、倒计时、快捷应用、背景图和天气。
- “历史记录”同时放系统趋势和浏览器本地操作日志；最有价值的趋势图默认收起，而操作日志价值较低。
- 主题预设与背景画廊同时平铺，数量过多，当前已选主题也不够突出。
- 多个页面使用高度相等的卡片网格，内容较少的卡片被拉得很高，形成大量空白。
- 辅助说明文字偏小、偏灰，长段说明占据主流程空间。
- RGB565、换字节、硬件反相等实现细节直接出现在普通主题页面，普通用户不需要理解这些信息。

### P2：可以进一步打磨

- 天气页先添加城市，再点击“为每个城市生成小屏页面”，步骤割裂；适合改成添加城市时直接选择“显示在屏幕上”。
- 宠物是有趣的个性化功能，但不是核心配置能力，不适合占据设置页一级标签。
- 音乐页的“正在播放”实际不显示歌曲或进度，标题与能力不匹配，可改为“媒体控制状态”。
- 快捷应用把原始命令直接暴露给普通用户，适合放到高级模式；默认界面使用应用选择器和动作模板。
- 命令面板对高频使用很有价值，但主要服务高级用户，不应替代清晰的主导航。

## 三、建议的新菜单结构

建议把当前六个一级菜单收敛为五个：

1. **概览**
   - 设备连接与当前应用版本
   - 需要介入的 AI 会话
   - CPU、内存、磁盘、网络摘要
   - 最近一次同步结果和快捷操作

2. **屏幕编辑**
   - 合并“任务视图”“页面编排”“主题与显示”“息屏显示”
   - 左侧页面树，中间 320×480 实时画布，右侧属性与组件库
   - 顶部统一显示设备、草稿状态、预览和“应用到设备”

3. **日程与控制**
   - 日程：提醒、日历、闹钟、倒计时
   - 控制：音乐、快捷应用、音量
   - 内容：天气、背景、宠物

4. **数据趋势**
   - CPU、内存、磁盘、网络、温度、风扇趋势
   - 异常事件和阈值标记
   - 操作日志作为次级标签，不再占据默认内容

5. **设置**
   - 设备与连接
   - AI 工具接入
   - 开机启动、数据保留、导入导出、诊断和固件升级
   - Web 外观与高级屏幕标定

## 四、统一修改与同步模型

建议取消每个卡片内重复出现的“保存配置 + 同步到设备”，改成全局状态栏：

`正在编辑 → 草稿已保存 → 等待设备 → 设备已应用 v32`

- 页面内修改立即更新 Web 预览，并自动保存本地草稿。
- 全局只保留一个主要按钮“应用到设备”。
- 设备离线时，按钮显示“设备离线”，同时允许继续编辑草稿。
- 只有收到设备应用版本回执后，才显示“已应用”。
- 提供撤销、重做、恢复上个设备版本和查看失败原因。

## 五、各页面处理建议

### 概览

保留设备状态、AI 会话、硬件摘要和常用操作。移除长期为空的天气、AI 用量和下一提醒占位；配置后再显示。卡片按内容自然高度排列，避免一张高卡把整行拉高。较长说明改成帮助按钮。

### 屏幕编辑

预设方案应使用单选卡或分段按钮，不能使用看起来可多选的复选框。组件禁用时显示明确原因，例如“本页已占满 4 个槽位”。自动按工具分页开启前显示将新增、删除或调整的页面，并允许锁定手工页面。

### 息屏显示

明确标出“设备当前使用”和“草稿选择”。底部操作栏保持吸附可见。只显示当前样式相关的诗词、相册或动画选项，并把闲置时长、夜间亮度和安静时段放在同一页。

### 日程与控制

新增提醒、日历或闹钟后，直接询问是否把对应组件放入某个页面。列表为空时提供清楚的新增入口和示例。提醒与闹钟要支持重复规则、暂停、稍后提醒、测试触发和设备执行记录。

### 主题与显示

首屏只展示“推荐、浅色、深色、我的主题”四组，每组少量方案。背景画廊单独打开。普通模式隐藏颜色管线术语，高级标定中展示“Web 请求色 → 屏幕实测色”的配置文件、导入导出和校准图。

### 数据趋势

趋势图默认展开。增加温度、风扇、网络收发和数据更新时间；鼠标悬停显示值和采样时间。异常阈值以事件标记呈现，并支持 CSV/JSON 导出。

## 六、后续功能路线

### 第一阶段：先完成配置闭环

1. 可视化 320×480 页面编辑器：拖页面、拖组件、2×2 与列表插槽、长文字溢出检查。
2. 全局草稿与设备版本状态：应用回执、失败原因、重试和恢复上一版。
3. 提醒、日历、闹钟、倒计时的完整创建、上屏、触发和确认流程。
4. 色彩校准档案：完整颜色映射配置、主题实时量化预览、设备档案绑定。
5. 修复连接状态、息屏选中态、组件禁用原因和传感器异常提示。

### 第二阶段：提升日常价值

1. 工作、会议、夜间等场景档案，一键切换页面、亮度和提醒策略。
2. 自动化规则，例如“AI 等待用户时闪烁”“温度超过阈值时提醒”“会议开始前切换日程页”。
3. 日历接入优先支持本地 ICS 导入，再评估系统日历或在线日历授权。
4. 硬件告警阈值、趋势事件、托盘通知和数据质量提示。
5. 音乐媒体会话增强：明确当前控制对象，条件允许时显示曲名、播放状态和进度。

### 第三阶段：扩展能力

1. 多设备管理与每台设备独立配置档案。
2. 配置备份、版本比较、主题与页面模板导入导出。
3. AI 工具接入管理，分别显示每个来源的连接、最后事件和权限状态。
4. 可选的动作组合和第三方扩展，但必须保留权限、执行回执和防重复触发。

## 七、暂时不建议继续投入的方向

- 在编辑与同步闭环完成前继续增加大量主题、背景和宠物形象。
- 扩充浏览器本地操作历史；它无法替代可靠的设备应用记录。
- 在普通界面增加更多原始命令或脚本输入。
- 增加更多静态概览卡片；没有数据时只会扩大空白与噪声。
- 仅增加模板数量而不完善拖放、校验、撤销和设备回执。

## 八、建议的实施优先级

最先处理：状态一致性和单一“应用到设备”闭环。  
第二处理：合并屏幕编辑入口，完成真正的可视化页面编辑。  
第三处理：打通提醒、日历和闹钟的完整流程。  
第四处理：趋势、自动化、日历接入和多设备等增强能力。

本轮已完成：

- 修复概览无 AI 会话时提前停止渲染的问题；设备连接、硬件数据和侧栏状态现在仍会正常刷新。

## 十二、Agent 状态兼容性审查与修复

当前能力分为两级，界面已经明确标注，不再统一写成容易误解的“运行中”：

| 工具 | 当前能力 | 可显示内容 |
|---|---|---|
| Claude Code | 会话状态 | 阶段、项目、任务类别、最近活动、等待/错误 |
| Codex | 会话状态 | 阶段、项目、任务类别、最近活动、等待/错误 |
| OpenCode | 会话状态 | 阶段、项目、任务类别、最近活动、等待/错误 |
| ZCode | 会话状态 | 阶段、项目、任务类别、最近活动、等待/错误 |
| WorkBuddy 智能体 | 会话状态 | 阶段、项目、任务类别、最近活动、等待/错误 |
| Cursor、Windsurf、Trae、VS Code、Zed | 仅进程检测 | 软件是否开启 |
| Gemini CLI | 仅进程检测 | 进程是否运行 |

Terminal、iTerm2、Warp 等只是终端宿主，不影响已支持 CLI 的采集；采集器读取 Agent 自身的本地日志或数据库。Aider、GitHub Copilot CLI、Cursor Agent CLI、Cline、Roo Code、Continue、Kiro 尚未接入会话解析，不能宣称已支持进度。

活跃任务通常没有工具提供的可信完成百分比。当前只在任务完成时显示 100%，执行中使用未知值；Web 已改为“完成度：工具未提供”，避免把阶段推断包装成百分比估算。

本轮修复了 Codex 长会话漏报：Codex 会继续写入会话创建日的目录，旧实现只扫描今天和昨天，恢复较早会话后无法发现。本次改为扫描所有会话路径并短时缓存目录结果，每轮仍检查文件修改时间；同时兼容新版 `custom_tool_call`、`custom_tool_call_output`、`reasoning` 和 `message` 事件。后台重启后，浏览器实测同时显示 ZCode 与当前 `maozi-diy` Codex 会话。

验证结果：客户端测试 `319 passed, 50 subtests passed`；JavaScript 语法和差异格式检查通过；实时 API 与浏览器概览均确认 Codex 会话恢复显示。
