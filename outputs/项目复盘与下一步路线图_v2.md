## 一、整体结构（四层 + 双端）

```
maozi-diy/
├── firmware/                  # 设备固件（C++ / LVGL / PlatformIO）
│   ├── src/
│   │   ├── main.cpp           # 主循环：采集 → 渲染 → 协议收发
│   │   ├── ui.cpp             # LVGL 界面渲染（最大改动面，+373 行在途）
│   │   ├── proto.cpp/.h       # 串口协议：telemetry / CFG / IMG / OTA / HB
│   │   ├── profile.cpp/.h     # 配置：A/B 双槽 + NVS 持久化 + card_opa 解析
│   │   ├── display.cpp        # ST7796 初始化（LovyanGFX）、亮度 PWM
│   │   ├── config.h           # 引脚 + 主题兜底色 + PANEL_COLOR_ORDER_BGR 开关
│   │   └── fonts/             # cn_20/24/32/48.c（Medium 500 字重，全 GB2312）
│   └── tools/gen_fonts.py     # lv_font_conv 封装，EXTRA 补非 GB2312 符号
├── client/workbuddy/          # 桌面上位机（Python）
│   ├── app.py                 # 主循环：psutil 采集 + 串口 + 状态快照
│   ├── web.py                 # HTTP 服务（CSP 严格：script/src 'self'）
│   ├── profile.py             # 配置校验器（对比度 3 项规则 + 17 项）
│   ├── aiwatch/               # 聚合 claude/codex/zcode/workbuddy 四来源会话
│   ├── tray.py / autostart.py # 系统托盘常驻 + 开机自启
│   ├── web_assets/            # index.html(已重建) / app.js(已重写) / app.css(令牌化)
│   └── tests/                 # 97 用例（profile/对比度/协议/导出导入/样式令牌/tray）
├── docs/                      # PROTOCOL / NEXT_MILESTONE / SMC_PRIVILEGED_PLAN / UI_REFACTOR_SPEC
├── outputs/                   # 历次分析报告（产品定位 / UI 审查 / 竞品 / 配色核验 / 样式修复）
└── firmware-diag/             # 独立诊断沙盒（LVGL 内存/编译验证），曾本地编译
```

**数据流**：固件 KV 串口 ↔ 客户端（psutil 采集 + aiwatch 聚合）→ 客户端经 USB 下发 CFG/IMG/OTA → 工作台 Web 设置页（HTTP 轮询 2.5s，无 WebSocket）读写 profile。

## 五、关键结论与建议执行顺序

1. **立即**：提交在途工作树（P0-3）——这是当前最高优先的"止损"动作，避免 30+ 文件改动丢失。
2. **本地**：`pio run` 编译（P0-1）→ 烧录 `PANEL_COLOR_SELFTEST=1` 判读 G/B（P0-2）。两步必须在你本地机器完成，本环境无法代劳。
3. **验收**：G/B 定论后，真机复核 P1-2（底部按钮/背景图）→ 前端 Playwright 冒烟 + 重打包（P1-1）。
4. **迭代**：再推进 P1-3/P1-4，及 P2 的 SMC helper（需你拍板是否投入特权采集）。

> 一句话：地基（编译 + G/B 配色）未定前，任何风格优化都会被掩盖；而**未提交的工作树是当前最该先锁定的资产**。
